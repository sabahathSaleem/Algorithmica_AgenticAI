Section 01

Core Concepts

Everything new in these two files — the async programming model from the ground up.

🛑

Synchronous (Blocking)

run_sync() — your Python thread stops completely and waits for the LLM response. Nothing else can happen. The CPU just sits idle waiting for a network reply. Simple and predictable — fine for scripts, terrible for servers handling many users.

one thing at a time
⚡

Asynchronous (Non-Blocking)

await agent.run() — Python suspends this task while waiting for the LLM, and can run other code in the meantime. When the LLM replies, Python resumes exactly where it left off. Same result, but the program stays productive during the wait.

do other things while waiting
⏳

await — The Pause & Resume Signal

The await keyword says: "start this slow operation, then give control back to the event loop until it finishes". You can only use await inside an async def function. It's not optional — omitting it would give you a coroutine object, not the result.

suspend here, resume later
🔄

Coroutine — An Async Function

Any function defined with async def is a coroutine. Calling it doesn't run it — it returns a coroutine object. To actually run it, you must either await it (inside another async function) or pass it to asyncio.run().

async def main()
🎡

Event Loop — The Async Scheduler

The event loop is Python's async task manager. It runs in a single thread, switching between coroutines at every await point. Think of it as a single waiter at a restaurant who takes orders from multiple tables — one person, many tasks.

asyncio's heart
🚀

asyncio.run() — Entry Point

The bridge between synchronous Python (normal scripts) and async code. asyncio.run(main()) creates an event loop, runs your async def main() coroutine to completion, then closes the loop. It's always the outermost call — never nest it inside another async function.

starts the event loop
💡 Why Does async Matter for LLM Applications?

An LLM call typically takes 0.5 – 3 seconds. In a sync server handling 100 users simultaneously, each user waits for all previous users' LLM calls to complete. With async, all 100 LLM calls are in-flight at the same time — the server fires them all, and as each responds, it gets processed. Same hardware, 10–100× more throughput. FastAPI, pydantic_ai agents with tools, and every serious LLM production system uses async.

The Restaurant Analogy

The best mental model for sync vs async — one waiter, different strategies.

⏸️

🍽️
Kitchen finishes. Waiter delivers food to Table 1.
2️⃣

agent.run_sync("question")
# CPU idle, waiting for network
⚡ Asynchronous Waiter (async.py)
1️⃣
Waiter takes Table 1's order, gives it to the kitchen (fires async call).
↩️
Waiter immediately goes to Table 2, then 3, then 4 — takes all their orders while kitchen is cooking.
🔔
Kitchen rings bell (LLM responds). Waiter delivers to Table 1 at the next opportunity.
⚡
All tables served faster with the same one waiter.
await agent.run("question")
# suspended, other code runs
🔑 The Key Insight

The LLM call is a network operation — the bottleneck is waiting for bytes to travel over the internet, not Python computing. During that wait, your CPU has nothing to do. Async lets Python use that idle time to serve other requests, handle other agents, or run other operations. The waiter (CPU) is always busy. Only the food preparation (network IO) takes time — and that's parallelisable.

Step-by-step execution of async.py

1
Module-level code runs normally
load_dotenv(), logfire.configure(), Agent() — all synchronous setup. Runs like any normal Python line. The async magic hasn't started yet.
2
asyncio.run(main()) — the event loop starts
asyncio.run() creates a new event loop, schedules the main() coroutine as the first task, then starts the loop. The loop runs until all tasks are complete, then closes.
3
async def main() begins executing
The event loop runs main(). Execution hits response = await agent.run(...). The await keyword is reached.
4
main() suspends, event loop takes over
await tells the event loop: "I need to wait for this network call. Suspend me, and wake me up when the result is ready." The LLM HTTP request is dispatched. Python is free to run other tasks.
5
LLM responds → main() resumes from line 4
The event loop detects the HTTP response is ready. It resumes main() exactly at the await line, with the response value. print(response.output) runs. asyncio.run() exits.
🔍 The Critical Rule — await Can Only Live in async def

await can only be used inside an async def function. That's why async.py wraps the agent call in async def main(). If you wrote await agent.run(...) at module level (outside any function), Python raises a SyntaxError.

And async def main() can only be called from another async function — or from asyncio.run() at the top level. The asyncio.run(main()) at the bottom of the file is the bridge between the sync world and the async world.

Commented Code — Both Files

Every import, every keyword, every design choice explained.

sync.py BLOCKING — run_sync() 
from dotenv import load_dotenv
from pydantic_ai import Agent
import logfire
# No asyncio import — sync code needs nothing special.
# This file is plain, linear, sequential Python.

load_dotenv(override=True)
logfire.configure()
logfire.instrument_pydantic_ai()

agent = Agent(
        #'groq:llama-3.3-70b-versatile',  ← commented: cloud alternative
    'ollama:llama3-groq-tool-use:8b',
        # Local Ollama model fine-tuned for tool use.
    # Both files use the same local model — sync vs async is about
    # HOW you call it, not WHICH model you use.
    instructions="You are a helpful assistant.",
)

response = agent.run_sync("Write a haiku about recursion in programming.")
# run_sync() is a SYNCHRONOUS wrapper around agent.run().
# Internally it does: asyncio.run(agent.run(...))
# — creates a temporary event loop, runs the async call, closes it.
# This is why you can call it from plain synchronous code.
#
# WHAT HAPPENS HERE:
# 1. Python sends the HTTP request to the Ollama local server
# 2. Python thread BLOCKS — os.waitIO() or equivalent
# 3. CPU does NOTHING while the LLM generates tokens
# 4. HTTP response arrives
# 5. Response parsed → RunResult returned
# 6. Execution continues to print() below
#
# Duration: typically 0.5–3s for a local model
# During that time: your entire Python program is frozen

print(response.output)
# RunResult.output = the LLM's text response as a Python string
print(response.usage())
# Token usage: prompt_tokens, completion_tokens, total_tokens
async.py NON-BLOCKING — await agent.run() 
import asyncio
# Python's built-in async I/O library.
# Provides: event loop, coroutine scheduling, async primitives.
# asyncio.run() is the gateway from sync → async world.

from dotenv import load_dotenv
from pydantic_ai import Agent
import logfire

load_dotenv(override=True)
logfire.configure()
logfire.instrument_pydantic_ai()
# These 3 lines run SYNCHRONOUSLY at import time — before the event loop starts.
# Logfire instruments pydantic_ai even in async mode — traces work the same way.

agent = Agent(
        #'groq:llama-3.3-70b-versatile',
    'ollama:llama3-groq-tool-use:8b',
    instructions="You are a helpful assistant.",
)
# Agent() created synchronously — the async magic is only in the CALL, not setup.


async def main():
        # 'async def' defines a COROUTINE FUNCTION.
    # Calling main() does NOT run it — it returns a coroutine object.
    # You must either: await main() (inside another async func)
    #              or: asyncio.run(main())  ← we do this at the bottom.
    #
    # Why wrap in a function? Because 'await' can only exist inside async def.
    # No async def → no await → can't use agent.run().

    response = await agent.run("Write a haiku about recursion in programming.")
        # 'agent.run()' (without _sync) returns a COROUTINE, not a result.
    # 'await' does three things:
    #   1. Starts executing the coroutine (sends HTTP request to LLM)
    #   2. SUSPENDS main() here — event loop takes over
    #   3. When LLM responds, RESUMES main() with the RunResult
    #
    # During step 2: Python event loop is free to run other tasks.
    # In a web server: it would handle incoming HTTP requests.
    # In multi-agent: it would advance other agents.
    # Here (single task): it just idles, but the pattern is in place.
    #
    # Note: agent.run() vs agent.run_sync()
    #   agent.run()      → async coroutine, must be awaited
    #   agent.run_sync() → sync wrapper, blocks the thread

    print(response.output)
    print(response.usage())
        # Same output as sync.py — the result is identical.
    # response.output is a string, response.usage() is a Usage object.
    # The difference is in WHEN these lines run, not WHAT they produce.


asyncio.run(main())
# THE BRIDGE: from sync Python world → async event loop.
# What asyncio.run() does:
#   1. Creates a new event loop
#   2. Schedules main() as the initial task
#   3. Runs the loop until main() completes
#   4. Cleans up and closes the loop
#
# RULES for asyncio.run():
#   ✅ Call at module level (like here)
#   ✅ Call once per program — it's the top-level entry point
#   ✗  Never inside another async function (use 'await' there instead)
#   ✗  Never inside a running event loop (IPython/Jupyter uses nest_asyncio)
#
# In a FastAPI app, you wouldn't need asyncio.run() at all —
# FastAPI manages the event loop itself and calls your async routes directly.
Section 07

When to Use Which — and What Comes Next

The practical decision guide for production GenAI systems.

🛑 Use run_sync() when…
✅
Writing a quick script or CLI tool
✅
Making a single LLM call — no concurrency needed
✅
In a Jupyter notebook (avoid asyncio.run() there)
✅
Testing / debugging — simpler to reason about
✅
Batch offline processing where speed doesn't matter
❌
In a web server — it blocks every other request
❌
When you need to run multiple LLM calls at once
⚡ Use await agent.run() when…
✅
Building a FastAPI / aiohttp web server
✅
Running multiple LLM calls concurrently with asyncio.gather()
✅
Building agentic pipelines where agents call tools and other agents
✅
Production systems where latency and throughput matter
✅
Already in an async context (async route handler, etc.)
❌
Don't introduce if you have a simple script — overkill
⚠️ The Cardinal Rule — Never Block in Async

If you use agent.run_sync() inside an async def function in a web server, you've introduced a blocking call that freezes the entire event loop — all other requests stop. The event loop can only work if you consistently use await for any I/O operation.

Rule: if you're in async code, everything I/O must be awaited. Never mix run_sync() inside an async context.

🚀 What asyncio.gather() Unlocks — Next Level

With async, you can fire multiple LLM calls simultaneously:

results = await asyncio.gather(
    agent.run("Question 1"),
    agent.run("Question 2"),
    agent.run("Question 3"),
)

All three LLM calls are in-flight simultaneously. Total time = max(call1, call2, call3) instead of call1 + call2 + call3. This is how agentic systems fan out work across multiple models — and it's only possible with await.
