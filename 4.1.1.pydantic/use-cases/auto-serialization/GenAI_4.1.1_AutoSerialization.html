Serialization — What & Why

Serialization means converting a Python object into a transportable format. You need it every time you: send data to an API, save to a database, return a response, or pass data to another service. Pydantic gives you three formats automatically — no writing your own conversion code.

object → transportable format
📋

model_dump() → Python dict

Returns the model as a plain Python dict: {"name": "Laptop", "quantity": 3, "price": 200.0}. Use when you need to pass the data to another Python function, update a database, or further manipulate it in Python before serialising.

returns dict
📤

model_dump_json() → JSON string

Returns a JSON-encoded string: '{"name":"Laptop","quantity":3,"price":200.0}'. Use when sending data over HTTP, writing to a file, or communicating with non-Python services. Faster than json.dumps(model_dump()) — Pydantic v2 uses Rust internally.

returns str (JSON)
📐

model_json_schema() → JSON Schema

Returns the JSON Schema of the model — a description of its structure, not its data. Tells any system: "this model has a string field called name, an int called quantity…". This is what pydantic_ai sends to LLMs as the tool definition for structured output.

returns schema dict
🔁

Content vs Structure Serialization

The code comments name it clearly: model_dump_json() = content serialization (the actual values). model_json_schema() = structure serialization (the shape of the data). These are complementary — LLMs need the schema to know what to produce; APIs need the content to transmit it.

Section 02

The 3 Serialization Methods

One object, three different outputs — each for a different destination.

p1.model_dump()
→ returns: dict
Converts the Pydantic model to a plain Python dictionary. Field names become keys; field values become values. Nested models become nested dicts. The output is a standard Python object — no JSON strings involved.
Use when:
  • Passing to another Python function
  • Updating a database with db.update(**p1.model_dump())
  • Merging with another dict
  • Pickling or further Python processing
p1.model_dump_json()
→ returns: str (JSON-encoded)
Serialises the model directly to a JSON string. Pydantic v2 uses a Rust-based JSON engine (pydantic-core) — significantly faster than json.dumps(p1.model_dump()). Handles types that plain json.dumps can't (datetime, Decimal, UUID, etc.).
Use when:
  • Sending over HTTP (REST API body)
  • Writing to a JSON file
  • Publishing to a message queue (Kafka, Redis)
  • Returning from a FastAPI endpoint
p1.model_json_schema()
→ returns: dict (JSON Schema)
Generates the JSON Schema of the model — describes the shape of valid data, not specific values. Follows the JSON Schema specification (Draft 2020-12). This is a class-level operation — the schema is the same regardless of instance values.
Use when:
  • Sending to an LLM as a tool definition
  • Generating API documentation (OpenAPI)
  • Validating incoming data against a spec
  • Sharing a data contract between services
⚡ model_dump() vs model_dump_json() — Don't Confuse Them

model_dump() returns a Python dict object. You can do d["name"] on it.
model_dump_json() returns a Python str containing JSON. You'd need json.loads() to use it as a dict again.

Common mistake: passing model_dump_json() to a function that expects a dict — it will get a string and fail. Use model_dump() for in-Python use; model_dump_json() for sending out of Python.

🔍 dict Quotes vs JSON Quotes

Notice: model_dump() output uses single quotes ('name') — that's Python's default dict repr.
model_dump_json() output uses double quotes ("name") — that's the JSON standard.
They look similar but are fundamentally different types. type(model_dump()) → dict. type(model_dump_json()) → str. If in doubt, check with type().

Section 04

model_json_schema() — Anatomy & Purpose

The most important method for AI/LLM integration — what every field in the schema means.

Full annotated JSON Schema for Product
{
"title": "Product",  ← class name. Used by tools to label the schema.
"type": "object",  ← top-level type is JSON object (dict).
"properties": {  ← describes each field.
"name": { "title": "Name", "type": "string" },  ← name: str → JSON type "string"
"quantity": { "title": "Quantity", "type": "integer" },  ← quantity: int → JSON type "integer"
"price": { "title": "Price", "type": "number" }  ← price: float → JSON type "number" (covers int+float)
},
"required": ["name", "quantity", "price"]  ← all 3 fields are required (no default values set → all mandatory)
}

🤖 model_json_schema() IS the LLM Tool Definition

When you write Agent(output_type=ProfileInfo), pydantic_ai calls ProfileInfo.model_json_schema() and wraps it in an OpenAI-compatible tool definition. The LLM sees the schema — including your Field(description=...) hints — and uses it to structure its response. Adding Field(description="Full name, properly capitalized") adds a "description" key inside the field's schema entry. The richer your schema, the better the LLM fills it in.

Section 06

Commented Code — Both Files

Every method call and its output explained with production context.

serialization1.py CONTENT + STRUCTURE SERIALIZATION 
from pydantic import BaseModel
# No ValidationError import needed here — we're not testing bad data.
# This file focuses entirely on EXPORTING a valid model, not input handling.

class Product(BaseModel):
    name: str
    quantity: int
    price: float
        # Same 3-field model from every file this week.
    # No Field() constraints — bare type annotations only.
    # model_json_schema() will produce a minimal schema (no descriptions).
    # Adding Field(description=...) would enrich the schema output.


p1 = Product(name="Laptop", quantity=3, price=200)
# Keyword arguments. price=200 (int) coerced to 200.0 (float) by Pydantic.
# p1 is a validated Product instance in memory.

print(p1)
# Calls __repr__ (auto-generated by Pydantic's BaseModel).
# Output: name='Laptop' quantity=3 price=200.0
# Pydantic's repr shows: fieldname=value for each field.
# Note: price shows as 200.0 (float), not 200 (int as passed).

print(p1.model_dump())
# Returns a plain Python DICT — not a string, not JSON.
# Output: {'name': 'Laptop', 'quantity': 3, 'price': 200.0}
#
# KEY USES:
#   db.products.update_one({}, {"$set": p1.model_dump()})   # MongoDB
#   cursor.execute("UPDATE ...", list(p1.model_dump().values()))  # SQL
#   {**p1.model_dump(), "extra_field": "value"}  # dict merging
#   another_function(**p1.model_dump())  # unpack into another function

print(p1.model_dump_json()) # content serialization
# Returns a JSON STRING — bytes-safe, network-transmittable.
# Output: {"name":"Laptop","quantity":3,"price":200.0}
# Double quotes = valid JSON. Single quotes would be invalid JSON.
#
# Pydantic v2 uses pydantic-core (Rust) for this — faster than:
#   import json; json.dumps(p1.model_dump())  ← slower Python equivalent
#
# KEY USES:
#   response.body = p1.model_dump_json()   # HTTP response
#   redis.set("product:1", p1.model_dump_json())  # cache
#   file.write(p1.model_dump_json() + "\n")  # newline-delimited JSON log
#
# NOTE: returns str, NOT dict. Type: str, not dict.

print(p1.model_json_schema()) # structure serialization
# Returns a dict describing the MODEL'S SHAPE — not p1's values.
# p1.model_json_schema() is the same as Product.model_json_schema()
# (schema is class-level, not instance-level).
#
# Output:
#   {
#     'title': 'Product', 'type': 'object',
#     'properties': {
#       'name': {'title': 'Name', 'type': 'string'},
#       'quantity': {'title': 'Quantity', 'type': 'integer'},
#       'price': {'title': 'Price', 'type': 'number'}
#     },
#     'required': ['name', 'quantity', 'price']
#   }
#
# THIS IS THE KEY TO pydantic_ai:
#   output_type=Product → pydantic_ai calls Product.model_json_schema()
#   → sends schema to LLM as tool definition
#   → LLM sees: "name (string), quantity (integer), price (number)"
#   → LLM responds with JSON matching this schema
#   → pydantic_ai validates response → returns Product instance
serialization2.py EXTERNAL DATA + FULL ROUNDTRIP 
from pydantic import BaseModel

class Product(BaseModel):
    name: str
    quantity: int
    price: float


external_data = {
    "name": "Laptop",
    "quantity": 3,
    "price": 200
}
# A plain dict — represents data arriving from OUTSIDE the application.
# Could be: requests.get(url).json(), json.loads(file.read()),
#           db.find_one(), kafka_message.value, or llm_response_json.
#
# Identical data to File 1 — but now it arrives as a dict, not hardcoded args.
# All values are correct here (File 2 of AutoValidation showed the failure case).
# This file focuses on the OUTPUT side, not the input error side.

p1 = Product(**external_data)
# **external_data unpacks the dict to keyword arguments:
# Product(name="Laptop", quantity=3, price=200)
# Pydantic validates: all values match their types → success.
# p1 is now a validated, typed Python object.
#
# This one-liner replaces:
#   p1 = Product(
#       name=external_data["name"],
#       quantity=external_data["quantity"],
#       price=external_data["price"]
#   )
# The ** approach scales to 50-field models with zero extra code.

print(p1)
# Output: name='Laptop' quantity=3 price=200.0
# Same as File 1 — the object is identical regardless of how it was created.

print(p1.model_dump())
# Output: {'name': 'Laptop', 'quantity': 3, 'price': 200.0}
# The dict is "round-trippable" back to a model:
#   p2 = Product(**p1.model_dump())  → works! (common pattern for copying)

print(p1.model_dump_json())
# Output: {"name":"Laptop","quantity":3,"price":200.0}
# Use case in this context:
#   After receiving from API → validate with Pydantic → re-serialise for
#   another downstream API. The "data pipeline" pattern:
#   API_A_response → Product(**resp) → p.model_dump_json() → POST to API_B

print(p1.model_json_schema())
# Same schema as File 1 — the schema describes the MODEL CLASS,
# not the specific values in p1.
# Product(**{"name":"Laptop",...}).model_json_schema()
#   === Product.model_json_schema()
# The schema is STATIC — same for every instance.
# Only changes when you add/remove fields or update Field() constraints.

🚀 The Complete pydantic_ai Pipeline — Now Fully Demystified

You now understand every step of what happens when you call agent.run_sync("tell me about India") with output_type=CountryInfo:

1. CountryInfo.model_json_schema() → generates schema → sent to LLM as tool definition.
2. LLM receives schema + prompt → responds with structured JSON.
3. CountryInfo(**llm_json) → validates and coerces (AutoValidation).
4. On success: response.output is a real CountryInfo object.
5. You can then: response.output.model_dump() → save to DB, or response.output.model_dump_json() → return via API.

That's the entire AI data pipeline — and you now own every layer of it.
