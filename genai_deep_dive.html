🌍 What even IS a "Python environment"?

Imagine your computer has a giant toy box with thousands of toys. But for your AI project, you only want specific toys — not ALL of them. A Python environment is like your own personal toy box — it only has the exact tools your project needs, and nothing else. This prevents different projects from fighting over different versions of the same tool.

Without environments: ❌ Project A needs numpy v1.0, Project B needs numpy v2.0 → they crash each other!

With environments: ✅ Each project has its own separate copy — they never interfere!

🎒 The School Bag Analogy

Think about school. For math class, you bring your math notebook, calculator, and ruler. For art class, you bring paints, brushes, and sketchbook. You don't carry everything for every class — that would be chaos!

A Python virtual environment is exactly your class-specific bag. For your AI project, the bag contains only the AI tools. For your web project, a different bag holds only web tools. Conda and venv are tools that create and manage these bags for you.

🤔 What is an LLM / AI Model?

An LLM (Large Language Model) is a huge computer program that has read billions of pages of text — books, websites, Wikipedia, code — and learned patterns from all of it. When you ask it a question, it predicts what a helpful, knowledgeable human would say based on all those patterns.

Think of it like this: if a person read every book ever written and memorized them, they'd know a lot! LLMs are that, but for computers — and they've "read" millions of times more than any human could.

An API (Application Programming Interface) is the doorway through which your Python code sends messages to these AI models running on powerful computers in data centers.

Imagine it's 1950 and you want to call different cities. You pick up the phone and tell the operator "Connect me to Chicago please". The operator plugs in the right cable and you're connected.

⚡ GPU vs CPU — The Hardware Race
Why do AI models need expensive GPUs? What's the actual difference? This section answers everything about the hardware that powers AI.

🧠 Understanding CPUs and GPUs from scratch

Your computer has two main processors. The CPU (Central Processing Unit) is the brain — it handles everything: running programs, managing memory, doing math. The GPU (Graphics Processing Unit) was originally designed to handle graphics for video games, but it turns out to be PERFECT for AI math too.

The key difference is how many calculations they can do at the same time. A CPU is great at doing a few complex things. A GPU is great at doing millions of simple things simultaneously.

🏊 Olympic Swimmers vs School Swimming Class

CPU = 8 Olympic gold medal swimmers. Each one is incredibly talented, highly trained, can swim butterfly stroke, freestyle, backstroke perfectly. But you only have 8 of them. If you need 100 swimming lanes filled, they can only do 8 at a time.

GPU = 10,000 regular school kids learning to swim. None are Olympic champions. But all 10,000 can swim their lane simultaneously. For tasks where you just need lots of lanes filled at once? 10,000 beats 8 every single time.

AI math = filling 10,000 swimming lanes. Training a neural network means doing millions of tiny multiplications all at once. The GPU's 10,000 "swimmers" win by a landslide!

📐 What is a Matrix? (The core AI operation)

Almost all AI calculations come down to matrix multiplication. A matrix is just a grid of numbers (like a spreadsheet). When you multiply two matrices, every number gets multiplied and combined with every other number. A 1000×1000 matrix multiply = 1 BILLION calculations!

A CPU does these 1 billion calculations one by one (or a few at a time). A GPU does them all at once in parallel. That's why GPUs are 50-200x faster for AI!

🔥 cpu-gpu.py — The Benchmark Race (3,070 bytes) Largest file in section ▶
🔍 What This Code Does Step by Step Creates two large random matrices (5000×5000 grid of numbers), multiplies them on the CPU and measures time, then repeats on the GPU and compares. The ratio tells you how much faster your GPU is!
🐍 cpu-gpu.py — fully annotated
import torch         # PyTorch: the #1 deep learning library
import time          # for measuring elapsed time

# ─── Step 1: Detect available hardware ──────────────────────
if torch.cuda.is_available():
    device = 'cuda'   # CUDA = NVIDIA's GPU computing platform
    print(f"GPU found: {torch.cuda.get_device_name(0)}")
    print(f"GPU memory: {torch.cuda.get_device_properties(0).total_memory/1e9:.1f} GB")
elif torch.backends.mps.is_available():
    device = 'mps'    # Apple Silicon Macs (M1/M2/M3 chips)
    print("Apple Silicon GPU found!")
else:
    device = 'cpu'
    print("No GPU — CPU only mode")

# ─── Step 2: Create large test matrices ─────────────────────
size = 5000   # 5000 rows × 5000 columns = 25 MILLION numbers!

# torch.rand() creates a matrix filled with random numbers 0.0–1.0
# Like rolling 25 million dice and recording all results
matrix_a = torch.rand(size, size)   # stored on CPU RAM
matrix_b = torch.rand(size, size)   # stored on CPU RAM

# ─── Step 3: CPU Race ────────────────────────────────────────
start_cpu = time.time()
result_cpu = torch.matmul(matrix_a, matrix_b)
# ↑ matmul = matrix multiplication
#   For each of 5000×5000=25M output cells,
#   it multiplies 5000 pairs and sums them: 125 BILLION operations!
cpu_time = time.time() - start_cpu
print(f"🐌 CPU: {cpu_time:.3f} seconds")

# ─── Step 4: GPU Race ────────────────────────────────────────
if device != 'cpu':
    # Move data from CPU RAM → GPU VRAM (graphics card memory)
    matrix_a_gpu = matrix_a.to(device)
    matrix_b_gpu = matrix_b.to(device)

    # IMPORTANT: synchronize() waits for GPU to finish
    # (GPU runs asynchronously — without sync(), timing is wrong!)
    torch.cuda.synchronize()
    start_gpu = time.time()

    result_gpu = torch.matmul(matrix_a_gpu, matrix_b_gpu)
    torch.cuda.synchronize()   # wait for ALL GPU work to complete

    gpu_time = time.time() - start_gpu
    speedup = cpu_time / gpu_time

    print(f"🚀 GPU: {gpu_time:.3f} seconds")
    print(f"⚡ Speedup: {speedup:.1f}x faster on GPU!")
    # Typical: GPU is 50x–200x faster than CPU!

🧩 Models & Providers — Two Ways to Configure AI
There are two styles of setting up your AI agent in pydantic-ai: the quick string method and the detailed object method. Each has its place.

🔤 The String Format Explained

When you write Agent('openai:gpt-4o-mini'), pydantic-ai parses that string and figures out everything automatically:

  • Before the colon = the provider (which company's servers to talk to)
  • After the colon = the model name (which specific AI brain to use)
  • It then looks in your environment variables for the corresponding API key
  • It automatically sets the correct base URL, request format, and headers
🛒 Supermarket Delivery Analogy

by-name.py (string approach) = Saying "I want to order from BigBasket". You just say the store name and they handle everything — picking items, packaging, routing.

by-object.py (object approach) = Calling BigBasket and saying "I want delivery to Building 5, Floor 3, use the rear entrance, fragile items on top, no bell — send me a text instead". You control every detail.

For most projects, the string approach is fine. Use object approach when you need custom endpoints, your own API gateway, or special HTTP settings.

The DRY Principle in AI Code

DRY = "Don't Repeat Yourself". Creating the model object once and sharing it across agents means if you want to switch from Groq to OpenAI, you change ONE line (the model creation) and all 3 agents automatically update. With string approach, you'd have to change each agent individually!

🎭 Agent Run Modes — Sync vs Async
Understanding when your program waits vs. when it can multitask is crucial for building responsive AI applications. This section explains both approaches deeply.

⏱️ What Does "Synchronous" vs "Asynchronous" Mean?

Synchronous (sync): Your program does ONE thing at a time, in order. It starts a task, WAITS until it's 100% done, then moves to the next task. Like a single-lane road — only one car can pass at a time.

Asynchronous (async): Your program can START a task and move on to other work WHILE the first task is still running. When the first task finishes, your program comes back to handle the result. Like a highway with multiple lanes — many cars move simultaneously.

☕ The Coffee Shop Analogy

Synchronous barista: Takes Customer 1's order → makes the coffee → hands it over → THEN takes Customer 2's order. Each customer waits in total silence. If coffee takes 3 minutes, Customer 2 waited 3 minutes doing nothing.

Asynchronous barista: Takes Customer 1's order → starts the machine → while coffee brews → takes Customer 2's order → starts their machine → takes Customer 3's order → machine beeps → gives Customer 1 their coffee → repeat. Everyone gets served faster!

In code terms: An AI API call takes ~1-3 seconds. Sync mode: your program freezes those 3 seconds. Async mode: your program starts the AI call and handles other requests while waiting. For a web server getting 1000 requests/minute, this difference is enormous!

🔄 The Event Loop — The Heart of Async Python

The event loop is like a super-efficient restaurant manager who never stands idle. It keeps a list of tasks. When a task is waiting (for network, disk, timer), the manager immediately moves to the next task. When the waiting task gets a response, the manager queues it to continue.

Without the event loop: one blocking operation (like waiting 2 seconds for AI) freezes everything. With the event loop: while waiting for AI, Python handles other tasks, reads other results, processes other data.

The Event Loop in action: Event Loop (runs forever, checking tasks): │ ├── Task A: awaiting AI response (paused, waiting 2s) │ ├── Task B: awaiting AI response (paused, waiting 2s) │ ├── Task C: has a result! ──► run Task C's next line of code │ ├── Task A: response arrived! ──► run Task A's next line of code │ └── Task D: new task! add to queue... KEY INSIGHT: Only ONE task runs at a time, but tasks YIELD CONTROL while waiting. No thread switching overhead, no locks, no race conditions!

        #   When thread finishes, result comes back via 'await'
        print(f"Result: {result}")

from pathlib import Path
import fitz  # PyMuPDF — install: pip install pymupdf
# ↑ "fitz" is the Python name for PyMuPDF (named after a historical project)
#   It can read PDFs, extract text, and convert pages to images

def pdf_to_images(pdf_path: str, output_dir: str,
                  dpi: int = 200) -> list[str]:
    """
    Convert each page of a PDF to a high-quality JPEG image.
    Returns list of image file paths.

    dpi=200 → good quality, reasonable file size
    dpi=300 → high quality, larger files (better for small text)
    """
    pdf_path = Path(pdf_path)
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)

    doc = fitz.open(pdf_path)
    image_paths = []

    for page_num in range(len(doc)):
        page = doc[page_num]

        # Matrix controls zoom level (higher = better quality)
        zoom = dpi / 72    # 72 is PDF default DPI
        mat = fitz.Matrix(zoom, zoom)

        # Convert page to pixel map (bitmap image)
        pix = page.get_pixmap(matrix=mat, colorspace=fitz.csRGB)

        img_path = output_dir / f"{pdf_path.stem}_page_{page_num}.jpg"
        pix.save(str(img_path), jpg_quality=85)
        # ↑ jpg_quality=85: good balance of size vs clarity

        image_paths.append(str(img_path))
        print(f"  Page {page_num+1}: saved to {img_path}")

    doc.close()
    return image_paths

def load_image_bytes(path: str) -> bytes:
    return Path(path).read_bytes()

    img_bytes = load_image_bytes(image_paths[0])  # use first page
    img = BinaryContent(data=img_bytes, media_type='image/jpeg')

    # ── Step 2: Categorize the document ──────────────────────────
    print("🔍 Categorizing...")
    cat_result = await categorizer.run([img, "What type of document?"])
    cat = cat_result.data
    print(f"   → {cat.category} ({cat.confidence:.0%} confidence)")

    # ── Step 3: Route to specialist agent ────────────────────────
    agent_map = {
        'invoice': invoice_agent,
        'payslip': payslip_agent,
        'driving_license': license_agent,
    }
    agent = agent_map.get(cat.category)
    if not agent:
        raise ValueError(f"No agent for: {cat.category}")

    # ── Step 4: Extract structured data ──────────────────────────
    print(f"📊 Extracting {cat.category} data...")
    ext_result = await agent.run([img, f"Extract all {cat.category} information."])

    # ── Step 5: Save as JSON ──────────────────────────────────────
    output_data = ext_result.data.model_dump()
    output_path = Path(pdf_path).with_suffix('.json')

    with open(output_path, 'w') as f:
        json.dump(output_data, f, indent=2)
    print(f"✅ Saved to: {output_path}")
    return output_data
