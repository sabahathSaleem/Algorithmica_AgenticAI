🗺 Same Models, Different Style — What Changed?

This is a refactored version of the earlier generic.py

The same 3 Pydantic models exist — FileElement, ModelAnalysisOutput, OCROutput. But the coding style has shifted: instead of field: str = Field(description="..."), every field now uses Annotated[str, Field(description="...")]. This is the modern, explicit Pydantic v2 style.

One field was also quietly removed: file_content_md (the full Markdown OCR text) is gone from ModelAnalysisOutput. And from typing import List is imported but never used — a leftover.

Section 01
🧠 New & Deepened Concepts
🏷

Annotated[ ] — Type + Metadata in One

Annotated[T, metadata] is Python's standard way to attach extra information to a type without changing the type itself. The first argument is the actual type. Everything after is metadata (like Field()).

🧒 Like: a name tag that says both "Hello my name is John" (the type) AND "Department: Engineering, Floor 3" (the Field metadata). One badge, all info.
🧩

Field() Inside Annotated

Putting Field(description="...", default="") inside Annotated[str, Field(...)] groups the type and its constraints together. Pydantic v2 reads Annotated metadata automatically and treats any FieldInfo object it finds as the field's configuration.

🧒 Like: instead of writing a student's name on the board AND on a separate sticky note, you write both on one ID card. Same data, tidier packaging.
🧱

Two Equivalent Styles

Both styles are 100% valid in Pydantic v2. Style A: f: str = Field(default=""). Style B: f: Annotated[str, Field(default="")]. They produce identical JSON schemas and identical validation behaviour. It's purely a code organisation choice.

🧒 Like: writing a recipe as a paragraph vs a numbered list. Same dish at the end — just different presentation. This file chose the numbered list style.
📋

Why Annotated is Preferred

When types get complex — list[FileElement] | None, validators, custom types — Annotated keeps everything in one clear place. It's also the style used by FastAPI, SQLModel, and modern Python libraries. Consistency across the ecosystem.

🧒 Like: using the same folder system everyone in your school uses. When you share your notes, others can find things immediately because the structure matches what they expect.
🗑

file_content_md Removed

The old version had file_content_md: str — a full Markdown OCR dump of the page. This version drops it. The agent now only extracts file_type and file_elements. The model no longer asks the AI to rewrite the full page as Markdown.

🧒 Like: a report that used to ask for a full transcript of the meeting + a bullet-point summary. Now it only asks for the summary. Faster, cheaper, more focused.
📦

from typing import List — Unused!

List (capital-L) from typing is the old Python 3.8 way to write a list type: List[str]. Python 3.9+ uses built-in list[str] directly. This file imports List but never uses it — it's a leftover from copy-paste. Safe to delete.

🧒 Like: buying both a new calculator and keeping your old broken one — you only use the new one. The old import is just sitting there taking up space.
🔒

file_elements — Now Required!

In the old version: file_elements = Field(..., default_factory=list) — had a default empty list. In this version: Annotated[list[FileElement], Field(description="...")] — no default. The field is now required. The AI MUST return elements.

🧒 Like: a form that used to allow "list of items: (leave blank if none)" now requires at least something. You can't submit an empty list — the AI must find at least one element.
🏭

default_factory in Annotated

For OCROutput.analysis_result, the default is set as Field(default_factory=ModelAnalysisOutput) inside Annotated. This still works perfectly — Pydantic reads default_factory from inside Annotated the same way as from a direct field assignment.

🧒 Like: whether you write "make a new blank form" on the back of the name tag or on a separate card — the instruction is the same. Pydantic finds it either way.

MODELS generic.py — Annotated style

Three Pydantic models using consistent Annotated[type, Field(...)] syntax throughout. Note the removed field and the unused import.

generic.py
from pydantic import BaseModel, Field
from typing import Annotated, List
# ☝️ Annotated: Python's built-in type annotation wrapper (from typing or 3.11+ natively)
#    List:      OLD-style list type from typing — List[str] same as list[str]
#    ⚠️ List is imported here but NEVER USED in this file!
#    The file uses lowercase list[FileElement] everywhere (Python 3.9+ syntax).
#    Safe to remove: from typing import Annotated  ← keep this one, remove List


# ═══ FileElement — one detected element on the page ══════════════════════
class FileElement(BaseModel):
    """Docstring — visible to the LLM as context for what this model represents."""

    element_type: Annotated[
        str,                          # ← SLOT 1: the actual Python type
        Field(
            description="Type of the element found on the page",  # guides AI
            default=""                  # ← SLOT 2: metadata — default makes it optional
        )
    ]
    # Full equivalent of old style: element_type: str = Field(description="...", default="")
    # Both produce IDENTICAL JSON Schema and validation behaviour.

    element_content: Annotated[
        str,
        Field(description="Content of the element found on the page", default="")
    ]


# ═══ ModelAnalysisOutput — LLM must return this shape ═════════════════════
class ModelAnalysisOutput(BaseModel):
    """Structured output for document analysis — output_type sent to Agent."""

    file_type: Annotated[
        str,
        Field(
            description="Type name: invoice, internal_document, instruction, other",
            default=""           # ← optional field (has a default)
        )
    ]

    # ⚠️ file_content_md is GONE in this version!
    # Old version had: file_content_md: str = Field(description="OCR markdown...", default="")
    # This field asked the AI to copy the FULL page content as Markdown.
    # Removing it makes the schema leaner and responses faster/cheaper.

    file_elements: Annotated[
        list[FileElement],            # ← list of nested Pydantic models
        Field(
            description="Elements the given page consists from: tables, images, paragraphs, graphs, flowcharts etc."
            # ☝️ NO default and NO default_factory here!
            #    This field is REQUIRED — the AI MUST return a list of FileElements.
            #    Old version had: default_factory=list → empty [] was OK.
            #    Now if the AI omits this field → ValidationError!
        )
    ]


# ═══ OCROutput — wrapper we build ourselves, not the AI output_type ═══════
class OCROutput(BaseModel):
    """We create this AFTER the agent responds — not sent to the AI as output_type."""

    filename: Annotated[str, Field(default="")]
    # ☝️ Compact inline style — single line when type + metadata are simple.
    #    Equivalent: filename: str = ""

    analysis_result: Annotated[
        ModelAnalysisOutput,
        Field(default_factory=ModelAnalysisOutput)
        # ☝️ default_factory works inside Annotated too.
        #    Pydantic v2 scans Annotated metadata for FieldInfo objects — finds it.
        #    Creates a fresh ModelAnalysisOutput() instance as default.
    ]

💡 When to use inline vs multiline Annotated

  • Inline: f: Annotated[str, Field(default="")] — short, simple types
  • Multiline: use indented blocks when description is long or type is complex
  • Consistency matters more than style — pick one and stick to it per file

💡 Pydantic v2 reads Annotated automatically

  • No special config needed — Pydantic scans Annotated metadata on startup
  • Any FieldInfo object found inside Annotated[...] is used as field config
  • Multiple metadata items can coexist: validators, constraints, BeforeValidator etc.

Section 04
⚠️ Gotchas & Best Practices

🚨 file_elements is now REQUIRED

No default_factory=list means if the AI response JSON doesn't include file_elements at all, Pydantic raises ValidationError: field required. Either add default_factory=list back, or ensure your prompt always elicits the field.

⚠️ Unused import: List

from typing import List is imported but never used — the file uses lowercase list[FileElement] everywhere. This is a lint error (F401 in flake8/ruff). Clean it up: remove List from the import line.

⚠️ Missing file_content_md downstream

If any other part of your codebase accesses result.analysis_result.file_content_md, it will now crash with AttributeError. Always search for usages of removed fields before deleting them.

🩷 Annotated multiline indentation

When Annotated fields span multiple lines, linters and formatters (black, ruff) may reformat them differently. Choose one style and configure your formatter to respect it. Consistency > personal preference in team codebases.

✅ Annotated enables reusable types

You can define a reusable annotated type alias: DescStr = Annotated[str, Field(description="...")] and reuse it across many models. Great for DRY code when many fields share the same constraints.

💡 list vs List — know the difference

Python 3.9+: use list[str] directly. Python 3.8 and below: must use from typing import List and write List[str]. Since this file uses list[FileElement], it requires Python ≥ 3.9. The unused List import is a Python 3.8 compatibility leftover.

🔮 default vs default_factory reminder

default="" — scalar values (str, int, float, bool) → safe to share.
default_factory=list — mutable types (list, dict, model instances) → must use factory to avoid shared state. Never default=[] or default=ModelAnalysisOutput().

✅ Both styles are valid — pick one

If your project mixes field: str = Field(...) and field: Annotated[str, Field(...)], consider standardising. The Annotated style is more future-proof and aligns with FastAPI/modern Python conventions — but consistency matters more than which you choose.

🗂 Annotated[ ] Quick Reference

🏷 Basic pattern
field: Annotated[type, Field(...)]
Type in slot 1. Field metadata in slot 2.
🔴 Required
Annotated[str, Field(description="...")]
No default in Field() = required. AI must provide it.
🟢 Optional
Annotated[str, Field(default="")]
Has default = optional. AI can skip it.
🔵 Nested list
Annotated[list[Model], Field(description="...")]
Array of objects. Each validated against Model.
🔮 Model default
Annotated[Model, Field(default_factory=Model)]
Creates fresh instance as default. Never default=Model().
⚠️ list vs List
Python 3.9+: list[str] ✅
Python 3.8: List[str] from typing
Don't mix — pick based on Python version.
