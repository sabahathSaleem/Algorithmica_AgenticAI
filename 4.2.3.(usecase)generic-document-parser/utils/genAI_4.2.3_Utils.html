Quick Reference
📋 4 Functions — What They Do

list_all_files()

INPUTfolder path + file extension (default "pdf")
OUTPUTlist[Path] — all matching file paths
Scans a directory and returns paths for every file ending in the given extension. One-liner using list comprehension.

pdf_to_jpg()

INPUTPDF path + save directory
OUTPUTlist[Path] — JPEG image paths, one per page
Renders each PDF page to a JPEG image using pdf2image + poppler. Uses a temp dir during rendering, saves final JPEGs to save_dir.

extract_text_from_pdf()

INPUTPDF file path
OUTPUTstr — all text from all pages joined
Reads raw embedded text from PDF using PyPDF2. Fast but limited — can't read scanned/image PDFs. Good for searchable PDFs only.

save_results_to_json()

INPUTfilenames str, results list, save_dir
OUTPUTNone — writes .json files to disk
Iterates over filename+result pairs and saves each as a JSON file. Uses Pydantic's model_dump_json(). ⚠️ Has a type mismatch bug — see bug section!
Section 01
🧠 Every Concept Explained
📂

os.listdir() + list comprehension

os.listdir(directory) returns a plain list of filenames as strings (not Paths). The list comprehension filters by extension using .lower().endswith(ext) and wraps each into a Path object.

🧒 Like: opening a folder, reading all file names, and picking only the ones that end in ".pdf" — like filtering mail by envelope type.
🖼

pdf2image + convert_from_path()

convert_from_path() uses Poppler (a C++ PDF renderer) under the hood. It converts each page of a PDF into a PIL Image object — the image as pixel data in memory, not a file yet.

🧒 Like: scanning each page of a physical book with a scanner. Each page becomes a photo in memory — then you save those photos as JPEGs.
🗂

tempfile.TemporaryDirectory()

with tempfile.TemporaryDirectory() as path: creates a temporary folder on your OS, runs the code block, then automatically deletes the folder and everything in it when the block exits — even if an exception occurs.

🧒 Like: borrowing a whiteboard at school — you use it, do your work, and it gets wiped clean when you leave the room. No mess left behind.
🖼

PIL Image + image.save()

Each element in the images list is a PIL Image object (from the Pillow library). Calling image.save(path, "JPEG") encodes it as JPEG bytes and writes to disk. The "JPEG" string is the format specifier.

🧒 Like: a photo exists as pixels in your camera's RAM → you press save → it gets encoded and written to the memory card as a .jpg file.
🏗

save_dir.mkdir(parents=True, exist_ok=True)

Creates the save directory if it doesn't exist. parents=True creates all parent folders in the path too (like mkdir -p on Linux). exist_ok=True doesn't error if the folder already exists.

🧒 Like: "Create the folder for me — and if it already exists, don't complain. Also create any parent folders if they're missing."
📖

PyPDF2.PdfReader

PdfReader(file) parses a PDF's internal structure. .pages returns a list of page objects. Each page's .extract_text() pulls out embedded text. Only works for text-based PDFs — not scanned images.

🧒 Like: copy-pasting text from a Word doc. Works perfectly if the PDF was made digitally. Fails if it's a photo of a document (scanned) — there's no real text to extract.
🔓

file.open(mode='rb') — Binary Read

mode='rb' opens a file in read binary mode. PDFs are binary files — they contain non-text bytes. You must open them as binary, not text ('r'), or Python's text decoder will crash on the binary data.

🧒 Like: reading a book vs reading a barcode. Text mode is for books (characters). Binary mode is for barcodes (raw bytes). Open the wrong way and it's gibberish.
🧪

model_dump_json() — Pydantic Serialisation

r.model_dump_json() is a Pydantic v2 method that converts a model instance to a JSON string. It handles nested models, date objects, and None values automatically. Returns a str, not a dict.

🧒 Like: a robot filling in a form → then taking a photo of the form → the photo is the JSON string. All the data is captured, packaged, ready to ship.
🤐

ensure_ascii=True in json.dump()

ensure_ascii=True (default) escapes all non-ASCII characters as \uXXXX sequences. Guarantees the output is pure ASCII — safe for any system. Set to False if you want readable Unicode (e.g., Hindi/Chinese characters preserved).

🧒 Like: translating a letter to use only English alphabet characters. "Café" → "Caf\u00e9". Safe to send anywhere but looks weird when you read the file.
🔗

zip(filenames, results)

zip(a, b) pairs up two lists element-by-element: [(a[0],b[0]), (a[1],b[1]), ...]. Stops when the shorter list runs out. Used here to pair each filename with its matching analysis result.

🧒 Like: matching answer sheets to student names. Student 1's sheet → result 1. Student 2's sheet → result 2. zip is the teacher pairing them up.
📁

Path(save_dir, f"{filename}.json")

Builds a file path by combining a directory and a filename with .json extension. Cross-platform — works on Windows (backslashes) and Linux/Mac (forward slashes) without you writing the separator manually.

🧒 Like: telling someone "go to the results folder and create a file called invoice_001.json." Path figures out the right slash for each OS.
🔢

enumerate(images) — Index + Value

for idx, image in enumerate(images): gives you both the loop counter (idx) and the item (image) at once. Used to build the filename: page_0.jpg, page_1.jpg, page_2.jpg ...

🧒 Like: a teacher handing out numbered question papers — "Paper 1, Paper 2, Paper 3..." instead of just handing them out with no number.

UTILS utils.py — 4 helper functions

Pure utility functions — no classes, no agents, no AI. Just Python file I/O, PDF processing, and JSON serialisation. The "worker hands" of the whole pipeline.

utils.py
# ═══ IMPORTS ══════════════════════════════════════════════════════════════
import json          # 📋 standard library — read/write JSON files
import os            # 📂 os.listdir() to scan directory contents
import tempfile      # 🗑 create + auto-clean temporary directories
from pathlib import Path          # 📁 cross-platform file path handling
import PyPDF2                       # 📖 read text from PDF files (text-based PDFs only)
from pdf2image import convert_from_path  # 🖼 render PDF pages → PIL Image objects
from models.generic import OCROutput    # 📦 Pydantic model for type hinting save function


# ═══ FUNCTION 1: list_all_files ═══════════════════════════════════════════
def list_all_files(directory: Path, extension: str = "pdf") -> list[Path]:
    return [
        Path(directory, f)                        # wrap each filename in Path object
        for f in os.listdir(directory)             # iterate all filenames in directory
        if f.lower().endswith(extension)           # keep only files ending in "pdf"
    ]
    # .lower() normalises: "Invoice.PDF" → "invoice.pdf" — catches uppercase extensions
    # extension="pdf" is the DEFAULT — caller can pass "jpg", "docx" etc.
    # os.listdir returns strings, not Paths → we wrap each in Path() for consistency
    # ⚠️ os.listdir does NOT guarantee order — add sorted() if order matters!


# ═══ FUNCTION 2: pdf_to_jpg ════════════════════════════════════════════════
def pdf_to_jpg(file_path: Path, save_dir: Path) -> list[Path]:
    save_dir.mkdir(parents=True, exist_ok=True)
    # ☝️ parents=True: creates full path, e.g. data1/temp_files even if temp_files doesn't exist
    #    exist_ok=True: no error if the folder already exists (safe to call multiple times)

    filename = Path(file_path).stem
    # .stem = filename WITHOUT extension: "invoice_001.pdf" → "invoice_001"

    image_paths = []                  # accumulate JPEG paths here

    with tempfile.TemporaryDirectory() as path:
        # ☝️ Creates a fresh temp dir (e.g., /tmp/tmpXy3k5p/).
        #    The 'with' block: temp dir is auto-DELETED after this block exits.
        #    Even if an exception occurs → cleanup happens. No leftover garbage!

        images = convert_from_path(file_path, output_folder=path)
        # ☝️ convert_from_path → uses Poppler (C++ PDF renderer) behind the scenes.
        #    Returns a list of PIL Image objects, one per PDF page.
        #    output_folder=path: tells Poppler to use temp dir for intermediate files.
        #    A 10-page PDF → images = [img0, img1, img2, ... img9]

        for idx, image in enumerate(images):
            # enumerate gives: (0, img0), (1, img1), (2, img2) ...
            # idx is used to build unique filenames: page_0, page_1, page_2

            save_path = Path(save_dir, f"{filename}_page_{idx}.jpg")
            # e.g.: data1/temp_files/invoice_001_page_0.jpg

            image.save(save_path, "JPEG")
            # PIL Image.save() encodes pixels → JPEG bytes → writes to disk

            image_paths.append(save_path)

    return image_paths
    # Returns list of Paths to the saved JPEG files on disk.
    # The temp dir is already cleaned up at this point.


# ═══ FUNCTION 3: extract_text_from_pdf ════════════════════════════════════
def extract_text_from_pdf(file_path: Path) -> str:
    with file_path.open(mode='rb') as file:
        # 'rb' = read binary — PDFs contain binary data, not just text characters
        # file_path.open() is pathlib style — equivalent to open(file_path, 'rb')

        pdf_reader = PyPDF2.PdfReader(file)
        # Parses the PDF internal structure — reads cross-reference table,
        # page tree, fonts, and embedded text streams.

        text = ""
        for page in pdf_reader.pages:              # iterate each page object
            text += page.extract_text()
            # extract_text() pulls embedded text from the page's content stream.
            # ⚠️ Returns "" for scanned/image PDFs — no text layer exists in them.
            # ⚠️ += on strings in a loop is O(n²) — use a list + "".join() in prod!

    return text
    # ⚠️ IMPORTANT: this function is defined but NOT called anywhere in this pipeline!
    #    The agents use image-based OCR (AI vision) instead.
    #    extract_text_from_pdf is a utility for future use or simpler non-AI flows.


# ═══ FUNCTION 4: save_results_to_json — ⚠️ CONTAINS A BUG! ══════════════
def save_results_to_json(
    filenames: str,                    # ⚠️ type hint says str but should be list[Path]!
    results: list[OCROutput],
    save_dir: Path
) -> None:

    for filename, result in zip(filenames, results):
        # zip pairs each filename with its corresponding result object.
        # ⚠️ zip(str, list) zips CHARACTER by character from the string!
        #    e.g. zip("abc", [r1,r2,r3]) → ('a',r1), ('b',r2), ('c',r3)
        #    This is almost certainly a bug — see bug section below.

        save_path = Path(save_dir, f"{filename.stem}.json")
        # .stem on a string character → AttributeError! str has no .stem attribute.
        # This confirms the type annotation bug — filename should be a Path object.

        with open(save_path, "w", encoding="utf-8") as f:
            json.dump(
                [r.model_dump_json() for r in result],
                # ☝️ model_dump_json() → converts Pydantic model → JSON string.
                #    This list comprehension iterates 'result' which is ONE OCROutput.
                #    Iterating a Pydantic model gives its fields, not sub-items.
                #    Should probably be: [result.model_dump_json()]  ← single item
                f,
                indent=4,             # pretty-print with 4-space indentation
                ensure_ascii=True    # escape non-ASCII → safe for all systems
            )
Section 02 — 🐛 Bug Hunt
🐛 Real Bugs Found in save_results_to_json()
🚨 Bug 1 — Wrong type hint: filenames: str should be filenames: list[Path]

The parameter is named filenames (plural) and used with zip(filenames, results) and filename.stem. This means it's expected to be a list of Path objects. The type hint str is incorrect. Python won't enforce type hints at runtime — but it misleads developers and type checkers (mypy/pyright will flag this).
✅ Fix: Change filenames: str → filenames: list[Path]
🚨 Bug 2 — zip(str, list) iterates characters!

If someone accidentally passes a str (matching the wrong type hint), zip("invoice_001", [result]) iterates character by character — giving ('i', result), ('n', result)... Then filename.stem crashes with AttributeError: 'str' object has no attribute 'stem'. The type hint bug enables this crash.
✅ Fix: Correct the type hint. In callers (agents_custom.py), pass pdf_path.stem (already a str from stem) OR pass the full Path and use .stem inside. Pick one and be consistent.
🚨 Bug 3 — Iterating over a single OCROutput

[r.model_dump_json() for r in result] — here result is ONE OCROutput object (not a list). Iterating a Pydantic BaseModel gives you its field names as strings, not sub-items. This would produce unexpected output or a TypeError.
✅ Fix: If saving one result per file: json.dump(result.model_dump(), f, indent=4)
Use .model_dump() (returns dict) not .model_dump_json() (returns string) when passing to json.dump() — otherwise you get a JSON-string-inside-JSON double encoding!

🚨 Double Encoding Bug

  • model_dump_json() returns a JSON string (e.g., '{"filename":"..."}')
  • Passing that string to json.dump() encodes the string again → "\"{\\"filename\\":\\"...\\"}\""
  • The JSON file becomes unreadable garbage
  • Use model_dump() (returns dict) when passing to json.dump()
  • Use model_dump_json() when writing directly with f.write()

✅ Correct Save Pattern

  • Option A: json.dump(result.model_dump(), f, indent=4) ✅
  • Option B: f.write(result.model_dump_json(indent=4)) ✅
  • Wrong: json.dump(result.model_dump_json(), f) ❌ double encode
  • Wrong: json.dump([r.model_dump_json() for r in result], f) ❌
Section 03
⚠️ Gotchas & Best Practices

🚨 PyPDF2 can't read scanned PDFs

extract_text_from_pdf() only works for PDFs with embedded text (created digitally). Scanned documents are images inside PDF — extract_text() returns empty string. That's why this pipeline uses AI vision (image OCR) instead.

⚠️ String concatenation in loop is O(n²)

text += page.extract_text() in a loop creates a new string each iteration. For PDFs with many pages, this is slow. Fix: texts = [page.extract_text() for page in reader.pages]; return "".join(texts)

⚠️ os.listdir has no guaranteed order

The files returned by os.listdir() are in arbitrary order (depends on filesystem). If your pipeline depends on processing files in alphabetical or date order, use sorted(os.listdir(directory)).

💡 Poppler must be installed separately

pdf2image is a Python wrapper for Poppler — a C++ library. pip install pdf2image alone isn't enough. You also need: Linux: apt install poppler-utils · Mac: brew install poppler · Windows: download Poppler binaries manually.

✅ TemporaryDirectory is self-cleaning

The with tempfile.TemporaryDirectory() block guarantees cleanup even on exceptions. This is critical in production — without it, every PDF conversion leaves temp files behind, filling up disk space.

🩷 extract_text_from_pdf is unused

This function is defined but never called in the current pipeline. The AI vision approach in agents_*.py is used instead. Keep it for non-AI fallback use cases, or delete to reduce dead code. Always document why unused code is kept.

🔮 ensure_ascii=True vs False

ensure_ascii=True: "Café" → "Caf\u00e9" — safe for all systems but hard to read. ensure_ascii=False: saves actual Unicode characters — human-readable but requires UTF-8 aware tools. For document processing (invoices, IDs), False is often more useful.

✅ model_dump() vs model_dump_json()

model_dump() → Python dict (use with json.dump). model_dump_json() → JSON string (use with f.write). Never pass a JSON string to json.dump — it double-encodes, producing invalid JSON-in-JSON.
