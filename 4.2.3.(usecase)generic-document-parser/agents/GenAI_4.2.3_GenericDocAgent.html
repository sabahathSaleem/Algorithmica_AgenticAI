📦 __init__.py — The Package Passport

🧒 What is __init__.py and why is it empty?

Python needs to know which folders are "packages" (importable) vs random folders. An __init__.py file — even empty — is the signal: "this folder is a Python package."

❌ Without __init__.py
The folder is just a regular folder. from models.generic import ... fails with ModuleNotFoundError.
✅ With __init__.py
The folder becomes a package. Python allows from models.generic import ModelAnalysisOutput to work.
🔮 Can Have Code Too
You can put code in __init__.py to run when the package is first imported — e.g., pre-import commonly used classes for shortcuts.
📁 Folder Structure

  __init__.py ← this file

  invoice.py
Without __init__.py, none of the models/ imports work.
PACKAGE MARKER __init__.py

Intentionally empty. Its presence is what matters, not its content.

__init__.py

# Its existence alone tells Python:

Section 01
🧠 New Concepts in This File
📊

tqdm — Progress Bar Library

tqdm (Arabic for "progress") is a Python library that wraps any iterable or async gather and shows a live progress bar in the terminal. You see: 3/10 [30%] ▓▓▓░░░░░

🧒 Like: a loading bar on a game download. Without tqdm you stare at a blank terminal. With tqdm you see exactly how many of your 50 pages have been processed.
⚡

tqdm.asyncio — Async-Aware tqdm

tqdm_asyncio.gather() is a drop-in replacement for asyncio.gather(). It does exactly the same thing — but also renders a progress bar as each concurrent task completes.

🧒 Like: upgrading from a plain timer to a stopwatch with a lap counter. Same underlying race, but you now see each runner cross the line.
🐦

Groq Provider

Groq is an AI inference company with custom hardware (LPU chips) designed for extremely fast LLM inference. Their models (like Llama-4) run much faster than on standard GPUs. GroqProvider routes calls to Groq's API.

🧒 Like: switching from a regular road to a Formula 1 track. Same car (Llama model), but the track (Groq hardware) is built for speed.
🦙

Llama-4 Scout (Meta)

meta-llama/llama-4-scout-17b-16e-instruct — Meta's Llama 4 model with 17B parameters in a Mixture of Experts (MoE) architecture with 16 experts. "scout" = smaller/faster variant. "instruct" = fine-tuned for instruction-following.

🧒 Like: a team of 16 specialists (experts). For each question, only 1-2 relevant experts activate — others stay quiet. Fast AND smart!
🔄

Variable Overwrite (Model Swap Pattern)

Defining model = OpenAIChatModel(...) then immediately model = GroqModel(...) overwrites the first. Only the second value is used. This is a quick "comment-swap" pattern for testing different models.

🧒 Like: writing "Pizza" on a whiteboard then erasing it and writing "Pasta". Only "Pasta" exists now. The pizza line is just there to quickly switch back.
🛡

raise e vs raise RuntimeError from e

This file uses raise e — re-raises the original exception unchanged. The previous files used raise RuntimeError from e — wraps the original error inside a new RuntimeError, preserving the chain. Both bubble up, but with different trace clarity.

🧒 Like: if your homework blows up: raise e = showing the teacher the exact page. raise RuntimeError from e = putting it in a cover sheet saying "this caused a bigger problem".
🔑

GROQ_API_KEY vs GITHUB_API_KEY

Each provider needs its own API key in .env. Groq uses GROQ_API_KEY, GitHub uses GITHUB_API_KEY. Both read with os.getenv(). You must have the right key for whichever model is active — the inactive model's key isn't used.

🧒 Like: different club memberships. Groq key = Groq club card. GitHub key = GitHub club card. Use the wrong one and you're denied entry.
📦

__init__.py — Package Marker

An empty file placed inside a folder to tell Python: "this folder is a package." Allows from models.generic import ... to work. Without it, Python sees just a regular directory, not an importable module.

🧒 Like: putting a mailbox outside your house. The post office (Python) now knows people live there and can deliver letters (imports) to you.
Section 02 — Key Design Decision
🔄 The Model Overwrite Pattern

🔵 Line 1: GitHub / GPT-4o

  • OpenAI GPT-4o model
  • Routes via GitHub AI API
  • Needs GITHUB_API_KEY
  • Multimodal vision support
  • Slower, higher quality
⛔ OVERWRITTEN — never runs
→

🟡 Line 2: Groq / Llama-4

  • Meta Llama-4 Scout 17B model
  • Routes via Groq's LPU hardware
  • Needs GROQ_API_KEY
  • Blazing fast inference speed
  • MoE: 16 experts, activates 2
✅ ACTIVE — this is what runs

⚠️ Why Define Both?

  • Quick toggle — comment one line to switch models
  • Useful for A/B testing: "which model extracts invoices better?"
  • In production, use a config file or env var to pick the model cleanly

✅ Better Pattern for Production

  • Use MODEL_PROVIDER=groq in your .env file
  • Read it with os.getenv("MODEL_PROVIDER")
  • Use an if/else to select the model — no silent overwrites
Section 03
📊 tqdm — What It Looks Like in Action
Terminal Output — with tqdm_asyncio.gather()
Processing pages...
7/10 [70%] ▓▓▓▓▓▓▓░░░ — elapsed: 4.2s — ETA: 1.8s — 1.67 it/s

vs. plain asyncio.gather() → blank terminal, no feedback, user thinks it crashed

💡 tqdm_asyncio.gather() vs asyncio.gather()

  • Both fire all tasks concurrently — identical performance
  • tqdm version wraps each completed task and updates the bar
  • The bar updates as tasks finish — faster tasks appear first
  • Accepts all same args: return_exceptions=True etc.

💡 Import Pattern

  • from tqdm.asyncio import tqdm_asyncio
  • Then use: await tqdm_asyncio.gather(*tasks)
  • Install: pip install tqdm — asyncio support included
  • Also works with tqdm_asyncio.as_completed() for ordered display

MAIN AGENT FILE generic_doc_agent.py

Updated generic OCR agent — same structure as agents_generic.py but with tqdm progress bars, Groq model, and a model-swap pattern baked in.

generic_doc_agent.py
# ═══ IMPORTS ══════════════════════════════════════════════════════════════
from tqdm.asyncio import tqdm_asyncio
# ☝️ tqdm = "progress bar" library. tqdm.asyncio is the async-aware version.
#    tqdm_asyncio.gather() = asyncio.gather() + live progress bar in terminal.

import os
from pathlib import Path
from dotenv import load_dotenv
from pydantic_ai import Agent, BinaryContent

# ─── OpenAI model via GitHub's AI API proxy ────────────────────────────────
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.github import GitHubProvider

# ─── Groq model — Meta Llama via Groq's lightning-fast LPU hardware ────────
from pydantic_ai.models.groq import GroqModel
from pydantic_ai.providers.groq import GroqProvider
# ☝️ PydanticAI supports multiple providers — same Agent interface regardless of provider.
#    Swap GroqModel ↔ OpenAIChatModel without changing any other code!

from pydantic_ai.settings import ModelSettings
from models.generic import ModelAnalysisOutput, OCROutput
# ☝️ This import ONLY works because models/__init__.py exists!
#    models/ is a package → Python lets us import from it.

load_dotenv()
# ← No override=True here (unlike agents_custom.py). Shell env vars take priority.


# ═══ MODEL DEFINITION — SWAP PATTERN ══════════════════════════════════════
model = OpenAIChatModel(
    "openai/gpt-4o",
    provider=GitHubProvider(api_key=os.getenv("GITHUB_API_KEY")),
    settings=ModelSettings(temperature=0)
)
# ☝️ GPT-4o defined here but immediately OVERWRITTEN below.
#    This line is kept as a "quick-switch" comment — to use GPT-4o,
#    comment out the Groq line below. That's the swap pattern.

model = GroqModel(
    'meta-llama/llama-4-scout-17b-16e-instruct',
    # ↑ Model ID breakdown:
    #   meta-llama/    → made by Meta (Facebook's AI research)
    #   llama-4-scout  → 4th generation, "scout" = smaller/faster variant
    #   17b            → 17 billion parameters total
    #   16e            → 16 experts (Mixture of Experts architecture)
    #   instruct       → fine-tuned to follow instructions (not just predict text)
    provider=GroqProvider(api_key=os.getenv("GROQ_API_KEY")),
    # ☝️ GROQ_API_KEY must be in .env — different key from GITHUB_API_KEY
    settings=ModelSettings(temperature=0)  # deterministic extraction
)
# ← This second assignment OVERWRITES the first. model = Groq. GitHub is gone.


# ═══ AGENT — identical to agents_generic.py ═══════════════════════════════
agent = Agent(
    model=model,                        # ← currently the Groq model
    instructions="You are an OCR expert specialized in the data extraction \
        from various types of documents. You are always precise and make sure \
        that extraction is done properly.",
    output_type=ModelAnalysisOutput,   # AI must return this Pydantic shape
)


# ═══ run_inference — process ONE image ════════════════════════════════════
async def run_inference(image_path: Path) -> OCROutput:
    message_parts = [
        "Extract the structure from the provided document.",
        BinaryContent(data=image_path.read_bytes(), media_type="image/jpeg")
    ]

    try:
        analysis_result = await agent.run(message_parts)
        print(f"File analyzed: {image_path.stem}")
    except Exception as e:
        print(f"Unexpected error while inference: {e}")
        raise e
        # ☝️ raise e — re-raises the ORIGINAL exception as-is.
        #    Different from agents_generic.py which used: raise RuntimeError from e
        #    See "raise diff" section below for the full breakdown.

    output = OCROutput(
        filename=image_path.stem,
        analysis_result=analysis_result.output
    )
    return output


# ═══ analyze_each_page — process ALL images in parallel with progress bar ═
async def analyze_each_page(image_paths: list[Path]) -> list[OCROutput]:
    tasks = [run_inference(path) for path in image_paths]
    # ☝️ Creates a list of unawaited coroutines — same as before, not yet running

    results_objects = await tqdm_asyncio.gather(*tasks)
    # ☝️ THE KEY CHANGE vs agents_generic.py:
    #    Before: await asyncio.gather(*tasks)         ← no progress, silent
    #    Now:    await tqdm_asyncio.gather(*tasks)     ← live progress bar!
    #
    #    Behaviour is IDENTICAL — concurrent execution, results in order.
    #    tqdm just wraps around it and prints: 3/10 [30%] ▓▓▓░░░░
    #    As each task finishes, the bar fills. Tasks completing out of order
    #    still update the counter correctly.

    return results_objects
Section 04 — Subtle but Important
⚡ raise e vs raise RuntimeError from e
⚡ This file — raise e
except Exception as e:
    print(f"Error: {e}")
    raise e

# Re-raises the EXACT same exception.
# Stack trace shows the original error.
# e.g.: ConnectionError: timeout
# Simple, clean.
🔗 Previous files — raise RuntimeError from e
except Exception as e:
    print(f"Error: {e}")
    raise RuntimeError from e

# Wraps original in a RuntimeError.
# Shows BOTH errors in traceback:
# "The above exception was the
#  direct cause of..."
# Better for API boundary clarity.

⚠️ There's also just raise (bare)

  • raise (no variable) = same as raise e inside except block
  • Preferred style: bare raise preserves the original traceback perfectly
  • raise e can sometimes reset the traceback line number — subtle bug
  • Best practice: use bare raise to re-raise, not raise e

✅ When to use each

  • raise — re-raise same exception, full traceback preserved
  • raise e — same but may lose exact line info (avoid)
  • raise RuntimeError from e — wrap + chain, for library APIs
  • raise ValueError("msg") from None — suppress original trace
Section 05
⚠️ Gotchas & Best Practices

🚨 Silent Model Overwrite

Defining model = OpenAI(...) then model = Groq(...) silently overwrites the first. If you forget which line is "active", you may use the wrong model in production. Use a config variable or comment clearly: # ACTIVE MODEL ↓.

⚠️ Wrong API Key for Active Model

If model is set to Groq but only GITHUB_API_KEY is in .env (not GROQ_API_KEY), you'll get an authentication error at runtime. Always double-check your .env matches the active model.

🩷 tqdm bar may look messy with print()

print(f"File analyzed: ...") inside the task will interleave with the tqdm bar, causing visual glitches. Replace prints with tqdm.write() inside tasks — it's tqdm-aware and won't corrupt the bar.

💡 load_dotenv() without override

Unlike agents_custom.py which used override=True, this file just calls load_dotenv(). That means shell environment variables take priority over .env values. Useful in Docker/cloud where env vars are injected externally.

✅ Groq is FAST — but not always best

Groq's LPU hardware gives you 5–10× faster token generation vs. standard GPU inference. But for complex vision tasks, GPT-4o may be more accurate. Speed vs quality — benchmark both for your specific document types.

⚠️ Llama-4 Vision Support

llama-4-scout-17b-16e-instruct has multimodal capabilities, but not all Groq model versions support image input. Always verify the model's vision support in Groq's docs before sending BinaryContent — or you'll get a silent failure.

🔮 MoE Models — What 16e Means

Mixture of Experts (MoE): the model has 16 "expert" sub-networks. For each token, only 2 experts activate. This gives GPT-4-level capability at a fraction of the compute cost. 17b total params but only ~3-4b active at once.

✅ __init__.py Best Practice

Always include __init__.py in your models/, utils/, and agents/ folders. Even empty — it makes imports predictable and works across all Python versions. Without it, behaviour varies by Python version and OS.
