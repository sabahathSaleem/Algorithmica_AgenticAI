Before the Code
Core Concepts You Need to Know
Think of this as your cheat sheet. Read this first — everything in the code will make sense immediately after.
🤖
What is an Agent?
An AI "worker" you create and give a job (instructions). You send it a message, it uses an LLM (like GPT or Llama) to think, and gives back an answer. Like hiring a smart intern with one specific role.
💬
What is Message History?
AI has no memory between calls. So you manually carry forward the conversation — like handing a new waiter the entire menu of what was already ordered.
📐
What is Pydantic?
A Python library that validates data shape. If you say "age must be an integer", Pydantic checks that and yells at you if someone passes in "twenty-five". Forces your data to be clean.
🔁
What is Multi-Turn?
A back-and-forth conversation — not just one question. Like texting a friend who remembers what you said 5 messages ago. The key is passing history each time.
🧩
What is Structured Output?
Instead of getting a messy paragraph from the AI, you get a neat Python object with fields like .name, .age. Like asking your friend to fill out a form instead of rambling.
🏭
What is Multi-Agent?
Multiple AI agents passing work between each other. Agent 1 does Step 1, hands the result to Agent 2 for Step 2. Like a factory assembly line but for AI tasks.
🧠 How PydanticAI fits together
The library wraps LLM calls with Python type safety + structured outputs + memory

Agent()
Creates your AI worker. Pass it a model name + instructions.
run_sync()
Sends a message to the agent and waits for the reply synchronously.
message_history=
Passes previous messages so the agent remembers the conversation.
new_messages()
Returns only the messages added in this last call — so you can append them to history.
all_messages()
Returns every message including the very first user prompt — useful when sharing context to another agent.
output_type=
Tells the agent what shape the output should be — a Pydantic model, a string, or Union of both.
logfire
Observability tool — logs every LLM call so you can debug what's happening in production.
Annotated[type, hint]
Pydantic way to add a description alongside a type — helps the LLM understand what to fill in.
File A
Multi-Turn Conversations
The simplest of the three. You chat back and forth with a single AI agent, and it remembers everything you said.
🎮
Think of it like a video game save file. Every message you send is saved to history. On the next message, you give the AI the whole save file so it knows everything that happened so far. Without history, the AI would have total amnesia every single message.
a_multi_turn_conversations.py
Beginner
What it does: Runs a loop in your terminal. You type a message, the AI responds, and it keeps building on the conversation. Type "q" to quit. Uses a local Ollama model.
python
1from pathlib import Path # not used here — probably leftover import
2from dotenv import load_dotenv # loads secrets from .env file (like API keys)
3from pydantic_ai import Agent # our AI agent class
4import logfire # a tool to log/track everything the AI does
5
6load_dotenv(override=True) # read the .env file — override any existing env vars
7logfire.configure() # set up logging/observability
8logfire.instrument_pydantic_ai() # tell logfire to watch pydantic_ai specifically
9
10# 🤖 Create an agent using a local Ollama model (llama3 with tool-use support)
11agent = Agent(
12 'ollama:llama3-groq-tool-use:8b', # which model to use — runs locally via Ollama
13 instructions="You are helpful assistant." # the agent's "personality/job description"
14)
15
16def main():
17 print("### Multi turn Conversations\n")
18 history = [] # 📦 empty bag — will hold all past messages
19
20 while True: # 🔄 keep looping forever until user quits
21 user_message = input(">>") # ⌨️ wait for the user to type something
22 if user_message == "q": # if user types "q", stop the loop
23 break
24
25 # 🚀 send the user's message to the agent
26 # IMPORTANT: we also pass history so the AI remembers the past
27 result = agent.run_sync(user_message, message_history=history)
28
29 print(result.output) # 🗣️ print what the AI replied
30 print(result.usage()) # 📊 print token usage stats (how much it "thought")
31
32 # 📝 CRUCIAL: add this turn's messages to our history bag
33 # new_messages() = only the NEW stuff from this turn (not everything)
34 history.extend(result.new_messages())
35
36if __name__ == "__main__": # only run main() if this file is run directly
37 main()
38
39# 💡 The comments at the bottom are sample prompts to test multi-turn memory:
40# "Provide me with a good motto for today!" ← turn 1
41# "Why did you choose this one?" ← turn 2 — refers to turn 1!
42# "How about another one for my friend?" ← turn 3 — still in context
🔑
The magic line is #34: history.extend(result.new_messages()). Without this, every message would be sent with no memory. This single line is what makes it "multi-turn".
⚠️
new_messages() vs all_messages(): new_messages() gives you only what was added in the LAST run. all_messages() gives you the whole conversation including the starting prompt. Here we use extend to keep building the history list.
File B
Extract Missing Info
The agent tries to extract a structured user profile from conversation. If any info is missing, it asks for it. Once complete, it returns a typed Pydantic object.
📋
Think of it like a smart form filler at a hospital. You walk in and say "Hi, I'm John." The receptionist (AI) checks the form — Name: ✅, Age: ❌, Favorite color: ❌ — and asks "What's your age?" It keeps going until the form is 100% filled. Then it hands you a neat data object.
b_extract_missing_info.py
Intermediate
What it does: Uses a Pydantic model (UserProfile) as the target. The agent either returns a filled UserProfile OR a str (a follow-up question). The loop keeps going until the AI confidently returns a UserProfile.
python
1from pydantic import BaseModel # base class for creating data models
2from pydantic_ai import Agent
3import logfire
4from dotenv import load_dotenv
5from typing import Annotated # lets us add metadata (descriptions) to types
6
7load_dotenv(override=True)
8logfire.configure()
9logfire.instrument_pydantic_ai()
10
11# 📦 Define the "shape" of data we want to collect
12# BaseModel = Pydantic's way of saying "this is a data structure"
13class UserProfile(BaseModel):
14 # Annotated[type, "description"] — the description helps the LLM understand what to extract
15 name: Annotated[str, "The user's full name"]
16 age: Annotated[int, "The user's age in years"] # must be a number, not "twenty"
17 favorite_color: Annotated[str, "The user's preferred color name"]
18
19# 🤖 Create the extraction agent on Groq's cloud (not local this time)
20agent = Agent(
21 'groq:llama-3.3-70b-versatile', # using Groq's fast cloud inference
22
23 # 🎯 KEY: output_type is a UNION — either a UserProfile OR a plain string
24 # If all info is found → returns UserProfile
25 # If info is missing → returns str (a question to ask the user)
26 output_type=UserProfile | str,
27
28 instructions=(
29 "Extract user profile information."
30 "If any fields are missing, do not guess. Instead, ask the user to provide the missing details."
31 # ☝️ "do not guess" is important — forces the AI to ask rather than hallucinate
32 )
33)
34
35def collect_info():
36 history = []
37 user_input = "My name is John." # 🧪 hardcoded first message — partial data on purpose!
38
39 while True: # keep looping until profile is complete
40 result = agent.run_sync(user_input, message_history=history)
41
42 # 🔍 Check what type the output is
43 if isinstance(result.output, UserProfile):
44 # 🎉 We got a complete profile! Print and stop.
45 print(f"Final Data Collected: {result.output}")
46 break
47 else:
48 # 🤔 AI returned a string — it's asking a follow-up question
49 print(f"Agent: {result.output}") # show the AI's question
50 user_input = input("You: ") # get user's answer
51 history.extend(result.new_messages()) # save this exchange to history
52
53collect_info()
💡
The Union type UserProfile | str is the hero here. It tells pydantic_ai: "the AI can return either a filled data object OR a plain text question." Your code then uses isinstance() to check which one it got — and responds accordingly.
🚫
"Do not guess" in the instructions is a guardrail against hallucination. Without it, the AI might invent an age (like 25) instead of asking. This is called "constraining the model's behavior with prompting."
File C
Multi-Agent Communication
Two different AI agents, on two different models, passing context between each other. Agent 1 generates content. Agent 2 receives that content and elaborates on it.
🏭
Think of it like an assembly line. Worker 1 (Ollama, local, cheaper) drafts a joke. Worker 2 (Groq, cloud, smarter) receives the joke in its context and explains why it's funny. They don't directly "talk" — they share a transcript of what happened.

c_multi_agent_communication.py
Advanced
What it does: Agent 1 (local Ollama) tells a joke. Its full conversation history is extracted via all_messages(). That history is given to Agent 2 (Groq) with the prompt "explain" — so Agent 2 knows what joke was told and explains it.
python
1from dotenv import load_dotenv
2from pydantic_ai import Agent
3import logfire
4
5load_dotenv(override=True)
6logfire.configure()
7logfire.instrument_pydantic_ai()
8
9# 🤖 Agent 1 — runs LOCALLY via Ollama (no internet needed, free to run)
10agent1 = Agent(
11 'ollama:llama3-groq-tool-use:8b', # 8 billion parameter model, local
12 instructions="You are helpful assistant."
13)
14
15# 🧠 Agent 2 — runs on GROQ CLOUD (faster, smarter, uses API key)
16agent2 = Agent(
17 'groq:llama-3.3-70b-versatile', # 70 billion parameters — much larger/smarter
18 instructions="You are helpful assistant."
19)
20
21# 🎤 Step 1: Ask Agent 1 to tell a joke
22# message_history=[] means starting fresh (no prior context)
23result = agent1.run_sync("tell me a joke, in short", message_history=[])
24print(result.output) # prints the joke 😄
25
26# 📋 Step 2: Grab Agent 1's FULL message history
27# all_messages() = includes the user prompt + the joke response
28# This is the "transcript" we'll pass to Agent 2
29history = result.all_messages()
30
31# 🧠 Step 3: Give Agent 2 the full history + ask it to "explain"
32# Agent 2 now has context: "User asked for a joke, Agent1 said XYZ"
33# So "explain" makes sense — it knows WHAT to explain
34result = agent2.run_sync("explain", message_history=history)
35print(result.output) # prints the explanation
🔑
The key insight: all_messages() is the bridge. It contains the user's original request + Agent 1's response. When passed as message_history to Agent 2, it's like showing Agent 2 a chat transcript before asking "what do you think?"
🏗️
Why use two different models? Cost + capability trade-off. Use a small, cheap local model (Agent 1) for simple tasks. Use a big, powerful cloud model (Agent 2) only when you need deeper reasoning. This is real-world agentic system design!
