Section 01

Core Concepts

The fundamental shift: from unstructured text to typed, validated Python objects.

📦

Structured Output

Setting output_type=MyModel forces the LLM to return JSON matching your Pydantic schema. pydantic_ai sends the schema to the LLM, receives JSON back, and parses it into a real Python object — not a string.

response.output is MyModel
🏗️

Pydantic BaseModel

Your schema is a Python class inheriting BaseModel. Each attribute is a field. Pydantic generates a JSON Schema, sends it to the LLM, validates JSON back, and coerces types. If validation fails, pydantic_ai retries automatically.

class MyModel(BaseModel)
🏷️

Annotated[type, Field()]

Annotated attaches metadata to a type. First arg = base type (str, int…). Second arg = Field() with validation rules + descriptions. This is the primary pattern for rich Pydantic models.

Annotated[str, Field(...)]
✅

Field() Validators

Field() holds constraints: ge=0, le=100, min_length, max_length, pattern (regex), description (guides LLM), examples (hints). Validation runs before your code sees the data.

runtime + LLM guidance
🔒

Literal Types

Literal["a","b","c"] means the LLM can only return one of those exact values — nothing else. Used for classification: the LLM picks from your allowed list. Pydantic rejects anything not in the literal set.

enum-like constraint
🪆

Nested Models

A field's type can be another BaseModel, or list[SubModel]. The LLM fills the full nested structure in one shot. pydantic_ai validates the entire tree — outer model, inner models, list items — all at once.

list[SubModel]

Section 02

Annotated[type, Field()] — Anatomy

The most important pattern in all 6 files. Every field follows this structure.

Dissecting a single field declaration
experience_years: Annotated[int, Field(description="Years of experience", ge=0, le=100)]
Annotated[...]
Python's metadata wrapper for types. Takes the base type first, then metadata. Pydantic reads the metadata automatically.
int
The base type. Could be str, int, bool, list[str], Literal[...], or another BaseModel.
Field(...)
Holds validation rules (ge, le, pattern…) AND schema metadata (description, examples) sent to the LLM.
Validation role (runtime)
ge=0, le=100 → if LLM returns -5 or 999, Pydantic raises ValidationError. pydantic_ai catches it and retries with a correction hint.
Schema role (guides LLM)
description="Years of experience" → included in JSON Schema sent to LLM. The LLM reads this to know what to put in this field. Better descriptions → better extraction.
🔑 Two Jobs of Field()

Field() serves two completely different audiences simultaneously:
1. The LLM — reads description= and examples= to understand what value to produce.
2. Pydantic validator — reads ge=, le=, min_length=, pattern= to check the value at runtime.
One decorator, two enforcement layers. This is what makes Pydantic + LLMs so powerful together.

🔒 Why Literal Beats a Prompt Instruction

You could write "classify into general, order, or billing" in the prompt and hope the LLM complies. Sometimes it'll say "This is an ordering question" — wrong format, unusable in code. Literal[...] is enforced by the JSON Schema enum constraint — the LLM sees it and must comply. And even if it doesn't, Pydantic rejects invalid values before your code ever sees them. Schema enforcement > prompt persuasion.

Section 06

Commented Code — All 6 Files

Every model, field, and validator explained in full context.

1_profile_info.pyEXTRACTION · list[str] · ge/le
from typing import Annotated
# Annotated: Python built-in for attaching metadata to types.
# Lets you put Field() validators alongside the type hint itself.

from pydantic import BaseModel, Field
# BaseModel: all Pydantic models inherit this.
# Field: descriptor for validation rules + LLM schema metadata.

class ProfileInfo(BaseModel):
        # This class IS the schema sent to the LLM as JSON Schema.
    # LLM must return JSON that matches this structure exactly.

    name: Annotated[str, Field(description="Full name, properly capitalized")]
        # "properly capitalized" is an INSTRUCTION embedded in the schema.
    # LLM reads this description and will transform "john" → "John".

    experience_years: Annotated[int, Field(description="Years of experience", ge=0, le=100)]
        # ge=0: must be ≥ 0 (no negative years)
    # le=100: must be ≤ 100 (catches hallucinations like 500 years)
    # Both are RUNTIME validators — Pydantic raises ValidationError if violated.
    # pydantic_ai catches the error and retries the LLM with a correction hint.

    skills: Annotated[list[str], Field(description="Technical skills found")]
        # list[str]: LLM returns a JSON array → parsed into Python list.
    # ["Python", "machine learning"] — not a comma-separated string.

agent = Agent(
    'groq:llama-3.3-70b-versatile',
    instructions="You are a helpful assistant to extract structure",
    output_type=ProfileInfo,
        # output_type= activates structured output:
    #   1. Generates JSON Schema from ProfileInfo
    #   2. Sends schema to LLM as tool/response constraint
    #   3. Parses JSON response → ProfileInfo instance
    #   4. Validates with Pydantic rules
    #   5. Returns ProfileInfo object as response.output
)

user_prompt = "john is an ai engineer with 5 years of experience, skilled in Python and machine learning."
response = agent.run_sync(user_prompt)
print(response.output)
# ProfileInfo(name='John', experience_years=5, skills=['Python', 'machine learning'])
# response.output.name → 'John' (string, capitalized by LLM instruction)
# response.output.experience_years → 5 (an int, not the string "5")
# response.output.skills → ['Python', 'machine learning'] (a real Python list)
2_address_info.pyREGEX PATTERN · examples= · ISO codes
class AddressInfo(BaseModel):
    first_name: Annotated[str, Field(min_length=1, max_length=50)]
        # min_length=1: can't be empty string
    # max_length=50: sanity cap
    last_name: Annotated[str, Field(min_length=1, max_length=50)]
    street: Annotated[str, Field(description="Street name or primary address line")]
        # description separates street from house number in LLM's mind.
    house_number: Annotated[str, Field(pattern=r"^[0-9a-zA-Z\s-]+$")]
        # pattern= is a REGEX applied to the string at validation time.
    # ^[0-9a-zA-Z\s-]+$ means: digits, letters, spaces, hyphens only.
    # Valid: "221B", "42", "10-A" | Invalid: "221B!!" → retry
    postal_code: Annotated[str, Field(min_length=3, max_length=10)]
    city: Annotated[str, Field(examples=["Berlin"])]
        # examples= is NOT a validator — it's a FORMAT HINT for the LLM.
    # Goes into JSON Schema as an example value. Tells the LLM:
    # "give me a city name like Berlin" — not a country or region.
    state: Annotated[str, Field(description="State or Province")]
    country: Annotated[str, Field(min_length=2, max_length=2, description="ISO 3166-1 alpha-2 code")]
        # min_length=max_length=2: exactly 2 characters.
    # description="ISO 3166-1 alpha-2" tells LLM to return "GB" not "United Kingdom".
    # Combined: enforced length + instructional description → "GB" guaranteed.

# Sherlock Holmes prompt → LLM extracts:
# AddressInfo(first_name='Sherlock', last_name='Holmes',
#   street='Baker Street', house_number='221B',
#   postal_code='NW1 6XE', city='London', state='England', country='GB')
3_classification.pyLiteral ENUM · TICKET ROUTER
from typing import Annotated, Literal
# Literal: type hint for a fixed set of allowed values.
# Different from Enum — it's a type annotation, not a class.

class TicketCategory(BaseModel):
    category: Annotated[
        Literal["general", "order", "billing"],
                # Pydantic generates: { "enum": ["general","order","billing"] }
        # LLM sees this enum and MUST choose exactly one.
        # Any other string → ValidationError → pydantic_ai retries.
        Field(description="The category of the ticket")
    ]

agent = Agent('groq:llama-3.3-70b-versatile',
    instructions="Classify the following message into a category",
    output_type=TicketCategory)

response = agent.run_sync("I would like to place an order.")
print(response.output.category)
# → "order" (guaranteed enum member — safe to use in routing logic)
# if response.output.category == "billing": route_to_billing_team()
response = agent.run_sync("I have a question about my billing.")
print(response.output.category)
# → "billing"
4_country_info.pyTYPE ALIAS · bool fields · KNOWLEDGE GEN
# ─── TYPE ALIAS ──────────────────────────────────────────────────────────────
Flag = Annotated[bool, Field(description="True if the country has a significant river or coastline")]
# TYPE ALIAS: assign a full Annotated[...] expression to a variable.
# "Flag" now IS that type — reusable anywhere like a built-in type.
#
# Why use aliases?
#   DRY: this bool + description combo appears in TWO fields (has_river, has_sea)
#   Single source of truth: change description once, both fields update
#   Readability: "has_river: Flag" cleaner than repeating the full Annotated[...]
#   Reusable: import Flag into other model files

class CountryInfo(BaseModel):
    continent_name: Annotated[str, Field(description="Name of the continent (e.g., 'Europe', 'Asia')")]
        # e.g. examples in description= are subtle format hints to the LLM.
    # "Europe" hint → returns "Asia" not "Asian continent".
    country_name: Annotated[str, Field(description="Official name of the country")]
    capital_name: Annotated[str, Field(description="Primary capital city of the country")]
    has_river: Flag
        # Expands to: Annotated[bool, Field(description="True if...")]
    # India → True (Ganges, Brahmaputra)
    has_sea: Flag
        # Same alias — same description. Both fields share identical semantics.
    # Australia → has_sea=True (Indian, Pacific, Southern Oceans)
    weather: Annotated[str, Field(description="Brief summary of the typical climate")]
        # "Brief summary" → LLM writes one sentence, not a paragraph.
5_planning_steps.pyNESTED MODEL · list[SubTask] · AGENT PLANNING
class SubTask(BaseModel):
        # INNER MODEL: not passed to Agent directly.
    # Used as the element type inside Plan.tasks: list[SubTask]
    task_id: Annotated[int, Field(description="Unique identifier for the subtask", ge=1)]
        # ge=1: task IDs start at 1 (not 0)
    # description="Unique identifier" → LLM auto-numbers: 1, 2, 3…
    description: Annotated[str, Field(description="Detailed description of the action to take", min_length=1)]
        # min_length=1: can't have empty description
    # "Detailed" hints: write a specific action, not just "Step 1"

class Plan(BaseModel):
        # OUTER MODEL: what output_type is set to.
    tasks: Annotated[list[SubTask], Field(description="List of ordered subtasks to achieve the goal")]
        # list[SubTask] → JSON Schema becomes an array of SubTask schemas.
    # "ordered" → LLM numbers subtasks in logical execution sequence.
    goal: Annotated[str, Field(description="The main objective of the plan")]

agent = Agent('groq:llama-3.3-70b-versatile', instructions="You are a helpful assistant to extract structure.", output_type=Plan)
response = agent.run_sync("Find the population of France and multiply it by 2, then summarize.")
print(response.output)
# Plan(
#   goal="Find, double, and summarize France's population",
#   tasks=[
#     SubTask(task_id=1, description="Search for the current population of France"),
#     SubTask(task_id=2, description="Multiply the found population by 2"),
#     SubTask(task_id=3, description="Summarize the result in a sentence"),
#   ]
# )
# In an agentic system: for task in response.output.tasks: execute(task)
6_math_steps.pyCHAIN-OF-THOUGHT · list[Step] · LOCAL OLLAMA
class Step(BaseModel):
    explanation: Annotated[str, Field(description="The step-by-step logic used to solve this part of the problem.")]
        # Captures the WHY: "Subtract 7 from both sides to isolate 8x"
    output: Annotated[str, Field(description="The mathematical result or expression derived in this step.")]
        # Captures the WHAT: "8x = -30"
    # Separating explanation from output forces structured reasoning — not a prose blob.

class Reasoning(BaseModel):
    steps: Annotated[list[Step], Field(description="A sequence of logical steps leading to the solution.")]
        # "sequence" → LLM keeps steps in logical order, not random.
    final_answer: Annotated[str, Field(description="The simplified final result of the mathematical problem.")]
        # "simplified final result" → LLM gives "x = -3.75" not a paragraph.

agent = Agent(
    'ollama:qwen3:4b',
        # LOCAL OLLAMA — not Groq this time!
    # Structured output is a pydantic_ai feature, not a provider feature.
    # output_type= works identically with Ollama, Groq, OpenAI, GitHub, etc.
    # The model must support JSON mode or function calling (qwen3 does).
        #'groq:llama-3.3-70b-versatile',  ← would also work perfectly
    instructions="You are a helpful assistant to extract structure.",
    output_type=Reasoning,
)
response = agent.run_sync("how can I solve 8x + 7 = -23")
print(response.output)
# Reasoning(
#   steps=[
#     Step(explanation="Subtract 7 from both sides", output="8x = -30"),
#     Step(explanation="Divide both sides by 8",     output="x = -30/8"),
#     Step(explanation="Simplify the fraction",      output="x = -3.75"),
#   ],
#   final_answer="x = -3.75"
# )
# Structured Chain-of-Thought:
#   - Show working step-by-step in a UI → for step in response.output.steps: render(step)
