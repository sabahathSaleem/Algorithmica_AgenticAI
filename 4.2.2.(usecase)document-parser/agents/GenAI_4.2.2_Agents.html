🗺 What Is This Code Actually Doing?

📄 "Here's a PDF of my invoice. Read it and give me
the vendor name, amount, and date — in JSON."

That's literally what this code does. But with AI instead of a human reading it.
1

📂 Find all PDF files in a folder

list_all_files(pdf_dir) scans a folder and returns a list of PDF file paths.

2

🖼 Convert each PDF page to a JPG image

pdf_to_jpg() renders each page of a PDF into a JPEG image. AI vision models understand images, not raw PDF bytes.

3

🤖 Send each image to GPT-4o / GPT-4.1 via API

The AI "looks" at the image and extracts information. It's like hiring an AI intern to read documents for you.

4

📋 Get back structured data (not just a chatbot reply)

Instead of "Here is the invoice data: ...", you get a proper Python object with fields like vendor_name, total_amount, date.

5

💾 Save results as JSON files

save_results_to_json() writes extracted data neatly into a JSON file for downstream use.

Section 01
🧠 Core Concepts — Explained Simply
📦

Pydantic BaseModel

A Pydantic model is like a form with labelled fields. You define what fields exist and what type of data goes in them. If the data doesn't match the type, Pydantic throws an error.

🧒 Think of it like: a school registration form. It has fields for "Name" (text), "Age" (number), "Class" (text). If you write "ABC" in the Age field — it's rejected!
🎯

output_type in PydanticAI Agent

When you set output_type=ModelAnalysisOutput, you're telling the AI: "Don't return a free-text reply. Return data that exactly matches this Pydantic shape." PydanticAI automatically validates and parses the response.

🧒 Like: asking your friend to fill out a form instead of texting you a paragraph. You get organised data, not a wall of text.
🖼

BinaryContent (Vision Input)

BinaryContent(data=image_path.read_bytes(), media_type="image/jpeg") reads an image file from disk and sends the raw bytes to the AI model along with a text instruction. This is how AI "sees" an image.

🧒 Like: emailing a photo to someone with the note "please describe what's in this image." The photo is BinaryContent; the note is the text prompt.
🔗

message_parts (Multimodal Prompt)

Instead of sending just text, you send a list containing both a text string and binary image data. This is a multimodal prompt — mixing multiple types of input in one message.

🧒 Like: showing a photo + asking a question at the same time, instead of just texting words. The AI sees both.
🕵️

Two-Agent Pipeline (Classify → Extract)

In agents_custom.py, two agents work in sequence:
1️⃣ Classifier Agent looks at the document and decides: "This is an invoice."
2️⃣ Extractor Agent now knows the type and uses the right schema to extract data.

🧒 Like: two workers. Worker 1 sorts mail into boxes (invoice/payslip/license). Worker 2 opens each box and fills out the matching form.
🗺

classification_to_schema (Dict Routing)

A Python dictionary maps string labels to Pydantic classes:
{"invoice": Invoice, "payslip": Payslip, ...}
After classification, we do .get(category) to pick the right schema dynamically at runtime.

🧒 Like: a menu board at a restaurant. You say "invoice", and you're handed the Invoice form. Say "payslip", you get the Payslip form.
🎭

Union Type: Invoice | Payslip | DriversLicense

This is Python type hinting syntax meaning "this variable can be any one of these three types." It tells both the programmer and the type checker that different document types are expected.

🧒 Like: a gift box that could contain either a book, a toy, or a game. You don't know which until you open it — but it's always one of those three.
⚙️

ModelSettings(temperature=0)

temperature controls how "creative" the AI is. 0 = deterministic, always picks the most likely token. Perfect for extraction tasks where you want consistency, not creativity.

🧒 Like: a calculator vs a poet. temperature=0 → calculator mode. temperature=1 → the AI gets creative and might say weird things.
🌐

GitHubProvider + OpenAIChatModel

Instead of using OpenAI directly, this routes through GitHub's AI model API. GitHub provides access to models like GPT-4o via a proxy. The GITHUB_API_KEY is the credential.

🧒 Like: calling a restaurant through a third-party delivery app instead of directly. Same food (model), different middleman (provider).
⚡

asyncio.gather() — Parallel Processing

All pages are sent to the AI simultaneously instead of one-by-one. gather(*tasks) fires all coroutines at once, slashing total processing time.

🧒 Like: emailing all your classmates at once vs waiting for each one to reply before emailing the next. Way faster!
🛡

try / except + raise RuntimeError

If the AI call fails for any reason (network error, model issue), the exception is caught, printed, and re-raised as a RuntimeError. This bubbles up cleanly to the caller instead of crashing silently.

🧒 Like: if your order fails at a restaurant, the waiter tells you instead of just disappearing. You know what went wrong.
📁

Path (pathlib)

Path is the modern Python way to work with file paths. Path(__file__).parent / "data1" builds a path relative to the current script location — works on Windows, Mac & Linux.

🧒 Like: "starting from this room, go to the room next door, then to the folder called data1" — platform-independent navigation.

GENERIC AGENT agents_generic.py

One agent that handles ALL document types with a universal schema. Good for "give me everything you see" extraction.

agents_generic.py
# ═══ IMPORTS ══════════════════════════════════════════════════════════════
import asyncio                       # ⚡ for gather() — run all pages in parallel
import os                            # 🔑 to read GITHUB_API_KEY from environment
import time
from pathlib import Path            # 📁 cross-platform file path handling
from dotenv import load_dotenv      # 🌿 load GITHUB_API_KEY from .env file
from pydantic import BaseModel, Field  # 📦 schema definition + field metadata
from pydantic_ai import Agent, BinaryContent  # 🤖 agent + image bytes container
from pydantic_ai.models.openai import OpenAIChatModel   # 🧠 OpenAI model wrapper
from pydantic_ai.providers.github import GitHubProvider  # 🌐 routes through GitHub AI API
from pydantic_ai.settings import ModelSettings           # ⚙️ temperature, max_tokens etc.
from utils import list_all_files, pdf_to_jpg, save_results_to_json  # 🛠 helper functions

load_dotenv()  # reads .env → sets os.environ["GITHUB_API_KEY"]


# ═══ SCHEMA: FileElement ══════════════════════════════════════════════════
class FileElement(BaseModel):
    """A single detected element on a page (table, paragraph, image, etc.)"""
    element_type: str = Field(
        description="Type of the element found on the page",
        default=""
    )
    element_content: str = Field(
        description="Content of the element found on the page",
        default=""
    )
    # ☝️ Field(description=...) tells the LLM what each field means.
    #    PydanticAI includes these descriptions in the JSON schema sent to the model.
    #    Better descriptions → more accurate extraction!


# ═══ SCHEMA: ModelAnalysisOutput — THE MAIN OUTPUT SHAPE ═════════════════
class ModelAnalysisOutput(BaseModel):
    """What the LLM must return — PydanticAI enforces this structure."""

    file_type: str = Field(
        description="Type name: invoice, internal_document, instruction, other",
        default=""
    )
    file_content_md: str = Field(
        description="OCR output: full contents of the page in Markdown",
        default=""
    )
    file_elements: list[FileElement] = Field(
        description="List of detected elements: tables, paragraphs, images...",
        default_factory=list  # ← default_factory=list means default is [] not None
    )
    # ☝️ list[FileElement] = a list where each item must be a FileElement object.
    #    Nested Pydantic models! The LLM returns a JSON array and it's auto-validated.


# ═══ SCHEMA: OCROutput — WRAPS FILENAME + RESULT ═════════════════════════
class OCROutput(BaseModel):
    """Final output: which file + what was extracted from it."""
    filename: str = ""
    analysis_result: ModelAnalysisOutput = Field(default_factory=ModelAnalysisOutput)
    # This is NOT sent to the LLM — it's assembled by us after the AI responds.


# ═══ MODEL + AGENT SETUP ═════════════════════════════════════════════════
model = OpenAIChatModel(
    "openai/gpt-4o",                      # 📌 model identifier (GPT-4o with vision)
    provider=GitHubProvider(
        api_key=os.getenv("GITHUB_API_KEY")  # 🔑 from .env file — never hardcode keys!
    ),
    settings=ModelSettings(temperature=0)   # 🎯 temperature=0 → deterministic, no creativity
)

agent = Agent(
    model=model,
    instructions="You are an OCR expert specialized in data extraction...",
    output_type=ModelAnalysisOutput,     # 🔒 LLM MUST return data matching this schema
)
# ☝️ output_type is the magic:
#    PydanticAI wraps your schema as JSON Schema, sends it with the request,
#    and validates the model's response. If invalid → it retries automatically!


# ═══ run_inference: process ONE image page ════════════════════════════════
async def run_inference(image_path: Path) -> OCROutput:
    message_parts = [
        "Extract the structure from the provided document.",  # 📝 text instruction
        BinaryContent(
            data=image_path.read_bytes(),   # 📸 read the image file as raw bytes
            media_type="image/jpeg"          # 📌 tell the model: this is a JPEG image
        )
    ]
    # ☝️ message_parts is a LIST = multimodal prompt.
    #    Index 0: text string — the instruction
    #    Index 1: BinaryContent — the image data
    #    The model receives BOTH simultaneously and processes them together.

    try:
        analysis_result = await agent.run(message_parts)
        # ☝️ agent.run() is async. The event loop pauses here while the API responds.
        #    Other pages can be processed while this one waits for the API!
        print(f"File analyzed: {image_path.stem}")  # .stem = filename without extension
    except Exception as e:
        print(f"Unexpected error while inference: {e}")
        raise RuntimeError from e  # wrap and re-raise — caller knows something failed

    output = OCROutput(
        filename=image_path.stem,
        analysis_result=analysis_result.output  # .output = the validated Pydantic object
    )
    return output


# ═══ analyze_each_page: process ALL pages in parallel ════════════════════
async def analyze_each_page(image_paths: list[Path]) -> list[OCROutput]:
    tasks = [run_inference(path) for path in image_paths]
    # ☝️ list comprehension builds coroutine objects — NOT started yet!
    #    Like preparing 10 envelopes before posting them all at once.

    results_objects = await asyncio.gather(*tasks)
    # ☝️ gather(*tasks) fires ALL coroutines simultaneously!
    #    If you have 20 pages → 20 API calls fly out at once.
    #    Total time ≈ slowest single page, not sum of all pages.

    return results_objects

CUSTOM TWO-AGENT PIPELINE 🎯 agents_custom.py

Two specialised agents working in sequence: Agent 1 classifies the document type → Agent 2 extracts data using the correct schema. Smarter but costs 2× API calls per page.

agents_custom.py
import asyncio, os, time
from pathlib import Path
from dotenv import load_dotenv
from pydantic_ai import Agent, BinaryContent
from models.invoice import Invoice           # 📄 Pydantic schema for invoices
from models.payslip import Payslip           # 💰 Pydantic schema for payslips
from models.drivers_license import DriversLicense  # 🪪 Pydantic schema for DL
from models.category import DocumentCategory  # 🏷 schema with .category field (string)
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.github import GitHubProvider
from pydantic_ai.settings import ModelSettings
from utils import list_all_files, pdf_to_jpg, save_results_to_json

load_dotenv(override=True)  # override=True: .env values beat any existing shell variables


# ═══ MODEL (GPT-4.1 — newer, faster than 4o) ══════════════════════════════
model = OpenAIChatModel(
    "openai/gpt-4.1",                         # 📌 note: gpt-4.1, not gpt-4o
    provider=GitHubProvider(api_key=os.getenv("GITHUB_API_KEY")),
    settings=ModelSettings(temperature=0)
)


# ═══ AGENT 1: CLASSIFIER ══════════════════════════════════════════════════
classifier_agent = Agent(
    model,
    instructions="You are a helpful assistant.",
    output_type=DocumentCategory  # → must return {category: "invoice"/"payslip"/"driver_license"}
)
# ☝️ classifier_agent's ONLY job: look at an image and say what type of document it is.
#    It returns a DocumentCategory object, e.g.: DocumentCategory(category="invoice")


# ═══ AGENT 2: EXTRACTOR ═══════════════════════════════════════════════════
extraction_agent = Agent(
    model,
    instructions="You are a helpful assistant."
    # ← NO output_type here! It's set dynamically at runtime per call.
)
# ☝️ extraction_agent is "schema-less" by default.
#    We inject the right output_type when we call agent.run(..., output_type=...)
#    This is the KEY trick that makes the pipeline dynamic!


# ═══ ROUTING MAP: string label → Pydantic class ═══════════════════════════
classification_to_schema = {
    "invoice": Invoice,
    "payslip": Payslip,
    "driver_license": DriversLicense,
}
# ☝️ This dict is the "switch board" / router.
#    category string → the Python class to use as the output schema.
#    .get(category) returns None if category isn't in the dict (handle this in prod!)


# ═══ run_inference: TWO-AGENT PIPELINE per image ══════════════════════════
async def run_inference(image_path: Path) -> Invoice | Payslip | DriversLicense:
    # ← Return type hint: could be any ONE of these three types

    # ─── Build message payloads (image bytes sent to BOTH agents) ───────────
    classifier_message_parts = [
        "Classify the type of the following document based on its content and structure.",
        BinaryContent(data=image_path.read_bytes(), media_type="image/jpeg")
    ]
    extractor_message_parts = [
        "Extract the structure from the provided document.",
        BinaryContent(data=image_path.read_bytes(), media_type="image/jpeg")
    ]
    # ⚠️ read_bytes() is called TWICE — the image is read from disk twice.
    #    Optimisation: read once → store in variable → reuse both times!

    try:
        print(f"##File analyzed: {image_path.stem}")

        # ─── STEP 1: CLASSIFY ────────────────────────────────────────────────
        classifier_response = await classifier_agent.run(classifier_message_parts)
        # ☝️ sends image to GPT-4.1 → "What type is this?" → returns DocumentCategory

        category = classifier_response.output.category
        # e.g.: category = "invoice"
        print(f"\n##Detected category: {category}")

        # ─── STEP 2: PICK THE RIGHT SCHEMA ───────────────────────────────────
        output_type = classification_to_schema.get(category)
        # e.g.: output_type = Invoice  (the Python class itself, not an instance!)
        # ⚠️ If category is unknown, output_type = None → extraction_agent.run() will fail!
        #    Add: if output_type is None: raise ValueError(f"Unknown category: {category}")

        # ─── STEP 3: EXTRACT WITH THE RIGHT SCHEMA ───────────────────────────
        extraction_response = await extraction_agent.run(
            extractor_message_parts,
            output_type=output_type  # 🎯 inject schema dynamically at call time!
        )
        # ☝️ Now the extraction agent knows exactly what fields to look for.
        #    For an invoice: vendor_name, amount, date, line_items etc.
        #    For a payslip:  employee_name, gross_pay, deductions etc.
        #    The AI is guided by the exact Pydantic schema fields + their descriptions.

        print(f"\n##Extracted data: \n{extraction_response.output}")

    except Exception as e:
        print(f"Unexpected error while inference: {e}")
        raise RuntimeError from e

    return extraction_response.output  # Invoice | Payslip | DriversLicense instance


# ═══ extract_structured_data: run ALL pages in parallel ═══════════════════
async def extract_structured_data(image_paths) -> list[Invoice | Payslip | DriversLicense]:
    tasks = [run_inference(path) for path in image_paths]
    results_objects = await asyncio.gather(*tasks)
    return results_objects


# ═══ workflow: THE MASTER ORCHESTRATOR ════════════════════════════════════
async def workflow():
    # ─── Build directory paths relative to this script ────────────────────
    pdf_dir = Path(__file__).parent.resolve() / "data1"
    # ☝️ __file__ = path to this .py file
    #    .parent   = the folder containing it
    #    .resolve()= convert to absolute path (no ".." shenanigans)
    #    / "data1" = append "data1" subdirectory (Path's / operator!)

    temp_dir    = pdf_dir / "temp_files"   # where JPEGs are stored temporarily
    results_dir = pdf_dir / "results"      # where JSON outputs are saved

    pdf_paths = list_all_files(pdf_dir)    # get list of all PDFs in data1/

    for pdf_path in pdf_paths:             # process each PDF one by one (sequential loop)
        image_paths = pdf_to_jpg(pdf_path, temp_dir)   # PDF pages → JPEG list
        results     = await extract_structured_data(image_paths)  # pages → async parallel
        save_results_to_json(pdf_path.stem, results, results_dir)  # save output
        # ⚠️ PDFs are processed sequentially, but PAGES within each PDF are parallel.
        #    To process all PDFs in parallel too: gather the workflow() calls.


# ═══ ENTRY POINT ══════════════════════════════════════════════════════════
if __name__ == "__main__":        # only runs if THIS file is executed directly
    start_time = time.perf_counter()
    try:
        asyncio.run(workflow())     # create event loop → run workflow → close loop
    except Exception as e:
        print(e)
    end_time = time.perf_counter() - start_time
    print(f"Analysis took: {end_time:.1f} seconds")

Section 05
⚠️ Gotchas & Best Practices

⚠️ read_bytes() called twice

In agents_custom.py, image_path.read_bytes() is called separately for classifier and extractor — reading the same file from disk twice. Store it: image_data = image_path.read_bytes() and reuse.

🚨 Unknown category → None schema

classification_to_schema.get(category) returns None if the model returns an unexpected value like "contract". This causes a silent failure. Always add: if output_type is None: raise ValueError(...)

⚠️ gather() fails on one error

asyncio.gather(*tasks) stops everything if one task raises an exception. For a batch of 50 pages, one bad page kills the rest. Use gather(*tasks, return_exceptions=True) to collect errors as values instead.

💡 PDF loop is sequential

The for pdf_path in pdf_paths loop processes PDFs one by one. Pages within a PDF run in parallel, but PDFs don't. For large batches, wrap the PDF loop in gather() too.

🔑 Never hardcode API keys

os.getenv("GITHUB_API_KEY") + load_dotenv() is correct. Never write the key directly in code. In production, use a secrets manager (AWS Secrets Manager, Azure Key Vault, etc.).

✅ Field descriptions = prompt engineering

The description= in every Field(...) isn't just documentation — it gets sent to the LLM as part of the JSON schema. Better descriptions = better extraction accuracy. Treat them like micro-prompts.

⚠️ Rate limits with gather()

Sending 50 images in parallel via gather() fires 50 API calls simultaneously. GitHub/OpenAI will rate-limit you. Use asyncio.Semaphore(5) to cap concurrent requests.

✅ temperature=0 for extraction

Always use temperature=0 for document extraction tasks. Higher temperatures introduce randomness that can corrupt structured outputs with hallucinated values. Save creativity for generation tasks.

= A form template. Defines what fields exist, what type they are, and what they mean.
🎯 output_type
= "AI, fill in this form." Forces structured output instead of free text. Can be set dynamically per call.
🖼 BinaryContent
= Sending a photo to the AI. Attach image bytes alongside your text instruction — multimodal prompt.
🕵️ Two-Agent Pipeline
= Worker 1 sorts mail. Worker 2 fills the right form. Classify first → extract with precision second.

= A menu board. Map string labels to Python classes. .get(key) picks the right schema at runtime.

= Post all letters at once. Fire all API calls simultaneously — total time = slowest call, not sum.
